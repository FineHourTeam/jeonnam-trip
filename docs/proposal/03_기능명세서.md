# 전남 축제 여행 플랫폼 기능명세서

작성일: 2026-10-16 · 버전 1.4 · 요구사항정의서와 함께 사용

## 1. 공통 상태와 데이터 관계

| 대상 | 주요 데이터·관계 |
|---|---|
| 장소 | 이름, 시군, 동네/권역, 종류·세부 종류, 주소·좌표, 영업구간·예외일, 정보 출처·확인일 |
| 개인 저장 | 계정과 장소 연결, 개인 태그·메모. 공통 장소와 별도 관리 |
| 원문 출처 | 플랫폼, URL, 공개 출처/개인용 구분, 장소와 다대다 연결 |
| 축제 | 시군, 개최 기간, 날짜별 운영시간, 위치, 프로그램, 주차·문의, 변경·취소 상태 |
| 크리에이터 코스 | 작성 출처, 장소·일차·순서, 순서 확인 기준, 검수일, 공개 상태 |
| 개인 코스 | 소유 계정, 여행 날짜, 이동수단, 여행 속도, 일차, 방문 후보, 고정 시각, 저장 버전 |
| 공유본 | 공개 허용 데이터만 추출한 코스 사본, 활성 상태, 공개 버전 |
| 여행 진행 기록 | 당일 모드 채택 시 소유 계정·코스·방문 항목 ID별 예정/완료/건너뜀·수정 시각. 순서 번호와 별개 식별자 사용 |
| 참여 초대·제안 | 친구 옵션 채택 시 초대 토큰·참여 권한, 제안자·장소·희망 일차·제안 상태. 개인 메모와 분리 |

공통 장소 수정, 개인 보관함 수정, 개인 코스 수정, 공유본 갱신은 다른 동작이다. 장소를 코스에 담을 때 이름·위치·당시 적용 정보의 사본과 원본 식별자를 저장해 변경을 비교할 수 있도록 설계한다. 사본을 보관한다는 이유로 변경·취소 안내를 생략하지 않는다.

영업시간은 ‘미확인’과 ‘휴무’를 구분한다. 공통 상태는 임시저장·공개·비공개이며, 공개 중인 데이터의 수정 초안은 기존 공개본을 유지하는 정책을 제안한다. 공개 여부와 자동 배치 적격 여부는 별도다.

## 2. 축제 조회와 코스 연결

관련 요구사항: 축제 조회·상세·일정 연결(FES-01~06), 지역 연결(REG-01)

입력은 시군, 조회 기간, 진행/예정 상태다. 조회 기간과 축제 개최 기간이 겹치면 노출하고, 기간 판정은 한국 표준시를 사용한다. 달력과 목록은 같은 결과를 사용한다.

상세에서 실제 방문일을 고른다. 일반 방문은 당일 운영시간 안에서 시작·체류를 설정하고, 특정 프로그램을 고르면 프로그램 구간을 고정한다. 개최 기간 전체나 당일 운영시간 전체를 체류로 사용하지 않는다.

‘이 축제로 여행 만들기’는 축제·날짜를 유지해 생성 설정으로 이동한다. ‘현재 일정에 추가’는 대상 일차와 기간 적합성을 검사한다. 취소된 축제는 상세를 볼 수 있으나 신규 추가를 막는다. 날짜별 운영시간 미확인은 수동 후보로 추가하고 확인을 안내한다.

축제 변경·취소는 최신 정보와 저장 당시 정보를 비교해 코스를 다시 열 때 알린다. 기존 일정은 사용자 확인 없이 수정하지 않는다. 푸시·이메일 자동 발송은 기본 과업으로 전제하지 않는다.

## 3. 장소 분류와 꺼내오기

관련 요구사항: 장소 분류·보관·꺼내오기(PLC-01~08)

기본 조회는 시군·종류·검색어다. 상세 필터에 세부 종류, 분위기·목적, 출처를 둔다. 동네/여행 권역은 행정구역과 구분해 운영팀이 정의한다. 주소가 없는데 권역을 자동 확정하지 않는다.

필터 정책 제안: 지역·종류·출처 등 다른 축은 AND, 같은 태그 묶음 안에서 복수 선택은 OR다. 세부 종류가 현재 상위 카테고리와 맞지 않으면 초기화하고 표시한다. 필터를 바꿔도 선택한 장소는 유지한다.

‘저장’은 개인 보관함에 연결한다. ‘일정에 추가’는 대상 코스·일차를 선택해 후보를 추가한다. 여러 장소를 한 번에 넣을 수 있다. 같은 일차에 이미 포함한 장소는 중복을 안내하며 반복 방문 허용 정책은 계약 전 정한다.

정보가 없으면 버리지 않는다. 좌표 미확인은 경로 계산에서, 영업시간 미확인은 자동 시간 배정에서 제외하고 수동 후보로 남긴다. 확정된 주차·예약·반려동물 정보와 주관적 분위기 태그를 분리한다.

## 4. SNS 링크 저장

관련 요구사항: SNS 링크 보관·장소 연결(SNS-01~04)

1. 원문 URL을 입력하고 허용 형식과 길이를 검사한다.
2. 미리보기 지원 여부와 관계없이 링크를 보관한다.
3. 사용자가 등록 장소를 검색·선택하거나 개인 장소를 입력한다.
4. 같은 원문에 다른 장소를 추가 연결한다.
5. 지역·종류를 확인하고 선택적으로 태그·메모를 더한다.
6. 계정 저장 시 로그인을 요청하고 입력 내용을 이어간다.

장소를 고르지 않으면 ‘장소 연결 전 링크’에 보관한다. 영상·설명에 장소가 없거나 댓글/메시지로 별도 제공되는 경우 서비스가 그 정보를 자동 확보한다고 안내하지 않는다. 사용자가 확인한 장소를 나중에 수동 연결한다. 지역도 모르면 미분류로 두며, 미연결 링크는 자동 코스 배치에서 제외한다. 영상 자동 분석이나 SNS 위치 태그 자동 추출을 전제로 하지 않는다. 장소의 정확한 주소·좌표 지정은 지도 위치 선택 또는 수동 보완 등 기본 구현 방법을 견적에 명시한다. 외부 검색 API 없이도 개인 장소 저장은 가능해야 한다.

SNS 원문 삭제·비공개 시 연결된 장소와 개인 메모는 보존한다. 접근 실패를 감지할 수 있는 경우 원문을 확인할 수 없다고 안내한다. 감지 수단이 없으면 삭제·비공개 상태를 알고 있는 것처럼 표시하지 않는다. 주기적 자동 링크 검사는 기본 범위로 전제하지 않는다. 서버에서 외부 URL 미리보기를 가져오는 경우 허용 주소·응답 크기·시간을 제한하고 내부 주소 접근을 차단한다.

## 5. 크리에이터 코스 복사

관련 요구사항: 크리에이터 코스 등록·복사·재검토(CRT-01~03)

운영팀이 원문·크리에이터·장소·일차·순서·확인 기준을 등록한다. 확인 가능한 것이 영상 등장 순서뿐이면 실제 여행 순서로 표현하지 않는다.

복사 시 여행 날짜·기간·자동차/도보를 받는다. 원본 장소와 순서를 개인 편집본으로 가져와 날짜별 영업과 축제 기간을 검토한다. 원본보다 짧은 기간을 고르면 넘치는 일차는 미배치 후보로 보존하고 사용자가 배치하도록 하는 안을 기본 제안한다. 프로토타입처럼 하루로 한꺼번에 합치는 동작은 최종 정책으로 확정하지 않았다.

휴무·기간 불일치·경로 조회 실패는 장소별 표시한다. 원본 유지, 개인 편집본 수정, 공개 공유본 갱신을 구분한다. 사용자가 수정한 버전을 크리에이터 원본 추천이라고 표시하지 않는다.

## 6. 일정 생성과 시간 계산

관련 요구사항: 일정 구성·영업시간 계산(PLN-01~11), 이동정보·재계산(MAP-02~05)

입력: 시작일·종료일(최대 4일), 추천/직접 만들기, 자동차/도보, 선택 장소, 일차별 시작·종료 시각, 선택적 출발·종료 위치, 고정 프로그램. 기본 시작·종료 시각과 준비 여유는 계약 전 확정하며 숨겨진 사용자 설정으로 간주하지 않는다.

여행 속도는 별도 메뉴 없이 최초 선택 화면의 날짜·이동수단과 함께 ‘여유롭게/알차게’로 제공한다. 생략하면 기본 추천 규칙을 사용한다. 여유롭게는 후보 수 상한을 낮추고 여유시간을 늘리며, 알차게는 제약을 만족하는 후보를 더 검토한다. 이동시간·최소 체류·고정 프로그램을 줄여 맞추지 않는다. 두 설정의 상한과 여유값은 계약 전 합의한다. 후보 부족 등으로 결과가 같으면 허용한다. 이미 작성한 일정의 속도만 바꿨다고 장소를 자동 삭제·추가하지 않으며 ‘추천 다시 받기’는 변경 내용을 확인하고 적용한다.

추천은 고정 프로그램을 먼저 놓고 적격 후보를 지역적 근접성·취향·영업 구간·이동시간으로 배치한다. 직접 만들기는 사용자의 순서를 유지하면서 검토한다. 최단 동선이나 최적해를 보장한다고 표시하지 않는다.

시간 계산은 추천과 직접 만들기 모두의 필수 기능이다. 식당·카페를 포함한 모든 방문 장소에 적용한다.

1. 순방향: 도착 = 이전 장소 출발 + 선택 이동수단의 실제 경로 예상시간 + 별도 접근 여유. 방문 시작은 도착과 이용 가능한 영업구간 시작 중 늦은 시각이며 대기는 체류와 구분한다.
2. 역방향: 다음 고정 일정의 목표 도착 시각(시작 시각 − 준비 여유) 또는 일일 종료 한도에서 출발한다. 중간 장소가 여러 개면 각 구간 이동·접근 여유와 필요한 체류시간, 각 장소의 영업조건을 차례로 빼며 앞 장소까지 출발·방문 시작 한도를 전파한다. 축제 바로 앞 장소만 검사하는 것으로 완료하지 않는다.
3. 현 장소의 이용 종료 한도 = 영업구간 종료와 후속 일정에서 역산한 출발 한도 중 이른 시각. 최대 체류 가능시간 = 이용 종료 한도 − 방문 시작. 자동 배정 체류는 기본 체류와 최대 가능시간 중 작은 값이며 최소 허용 체류 미만이면 방문 가능한 일정으로 확정하지 않는다. 사용자가 직접 고정한 체류시간은 임의로 줄이지 않는다.
4. 휴무·브레이크타임·확인된 라스트오더/입장 마감을 별도로 검사한다. 라스트오더는 방문·주문 가능 여부의 조건이지 모든 이용을 종료해야 하는 시각으로 간주하지 않는다. 정보가 없으면 미확인으로 표시한다. 여러 영업구간은 구간별로 검토하며 휴게시간을 가로질러 연속 체류를 배정하지 않는다.
5. 순방향으로 가능한 방문 시작이 역산한 한도보다 늦으면 충돌이다. 추천은 다른 시간대·후보를 검토하고 미배치 이유를 남긴다. 직접 편집은 사용자 순서를 유지하며 앞당김·체류 조정·장소 교체·일차 변경 등 해결 동작을 제시한다. 적용 가능한 대안을 찾지 못하면 불가능/확인 필요 상태를 유지한다.

자동차와 도보의 이동시간은 각 수단의 경로 조회 결과를 사용한다. 주차·접근·준비 여유는 경로 시간과 구분하고 중복 합산하지 않는다. 기본 여유와 장소별 최소 체류 기준은 계약 전에 정한다. 경로 또는 영업시간이 없으면 해당 구간과 영향받는 일정을 미확정으로 표시하며 실행 가능하다고 보증하지 않는다.

검수 예시(가상 입력): 축제 14:00 시작, 준비 10분, 식당→축제 자동차 20분, 식사 60분이면 식당 출발 한도 13:30, 이용 시작 한도 12:30이다. 식당이 13:00 개점하고 최소 식사가 60분이면 충돌이다. 라스트오더 12:00인데 12:30에 방문하는 경우도 충돌이다. 동일 구간 도보 조회가 50분이면 출발 한도는 13:00, 이용 시작 한도는 12:00으로 변경된다. 앞에 카페를 추가하면 카페→식당 이동과 식당 영업조건까지 연쇄 역산한다. 경로 조회 실패는 이전 시간을 확정값으로 사용하지 않는다. 이 수치는 계산 검수용이며 실제 장소의 정보가 아니다.

초기 체류값 제안: 축제 150분, 식당 60분, 카페 45분, 상점 40분, 관광지 90분. 영업 시작 전 대기는 체류와 별도 표시한다. 주문/입장 마감이 확인되면 추가 제한으로 적용한다. 휴게시간을 가로질러 연속 방문 가능하다고 계산하지 않는다. 자정을 넘는 영업구간의 지원 여부는 데이터 형식과 함께 확정한다.

출발·종료 위치가 없으면 첫 장소부터 마지막 장소까지만 합산한다. 숙소는 일차 사이 이동의 기준점이며 숙박을 일반 관광 체류로 계산하지 않는다. 숙소 미정이면 연결 동선을 잠정으로 표시한다.

## 7. 편집과 경로 조회

장소 추가·삭제·교체·순서 변경 시 변경 구간과 후속 도착시각을 다시 계산한다. 다른 일차 이동은 양쪽 날짜 조건을 다시 검사한다. 사용자 고정 시각은 유지한다. 빠른 연속 편집에서는 이전 조회 응답이 최신 편집을 덮어쓰지 않도록 한다.

지도에는 실제 조회된 경로를 표시한다. 직선 반경 탐색을 실제 도로거리로 표기하지 않는다. 자동차·도보를 각각 지원하는 데이터 제공 방식을 업체가 제안한다. 현재 교통 기반 예상치와 미래 날짜의 예측 가능 범위를 구분한다.

조회 실패 시 편집은 보존하고 구간 및 후속 도착시각을 미확정으로 표시한다. 이전 값은 ‘재계산 전’으로 구분하며 재시도를 제공한다. 일부 구간 실패 시 합계를 완전한 값처럼 표시하지 않는다.

## 8. 저장과 공유

연결: ACC-01~02, SAV-01~02, SHR-01~03

저장 시 비회원이면 작성 내용을 보존하고 로그인한다. 취소·실패 후에도 작성 화면으로 돌아간다. 실제 서버 성공 응답 전에 완료를 표시하지 않는다. 소유권 검사는 화면뿐 아니라 서버 데이터 요청에 적용한다.

공유 전 공개 제목·날짜·방문 장소·시간·위치를 미리 보여준다. 개인 메모·개인 출발/종료 주소·개인용 SNS 링크는 기본 제외한다. 공개 콘텐츠의 원문 출처는 유지한다. 개인 입력 장소도 공개 대상이라면 미리보기에서 확인시킨다.

공유 사본 정책 제안: 공개 시점 사본을 만들고, 개인 코스 수정은 공개본에 자동 반영하지 않는다. 사용자가 미리보기에서 ‘공유 내용 업데이트’를 선택하면 갱신한다. 공유 해제와 코스 삭제는 링크 접근을 차단한다. 이미 타인이 복사한 개인 코스는 회수하지 않는다.

로그아웃 시 현재 기기의 개인 데이터 표시를 정리한다. 계정 삭제 시 개인 장소·코스·공개 링크와 보관기간의 처리 정책을 확정한다. 동시 기기 편집은 오래된 저장이 최신 결과를 조용히 덮어쓰지 않도록 버전 충돌을 안내하는 방안을 협의한다.

## 9. 운영 관리

연결: ADM-01~03

필수 입력과 미확인 허용 항목을 구분한다. 이름·지역·축제 개최 기간·출처·확인일의 공개 전 필수 여부를 콘텐츠별로 확정한다. 임시저장은 불완전 정보도 허용한다. 입력 형식 검사는 사실 검증을 대신하지 않는다.

축제 취소 정보는 공개 상태에서 표시할 수 있으나 신규 일정 추가 대상에서는 제외한다. 운영시간 없는 장소는 공개해 탐색·수동 보관을 허용하고 자동 시간 배정에서는 제외한다. 크리에이터 코스는 등록 장소를 연결해 순서를 구성한다.

관리자 미인증·일반 사용자는 운영 API에 접근할 수 없어야 한다. 변경 주체·일시 기록 범위와 관리자 계정 발급·복구 담당은 계약 전 합의한다.

## 10. 당일 모드

연결: DAY-01~04 · 1차 추가 견적, 채택 후 구현

저장 코스에 ‘계획 보기/여행 시작’ 전환을 제공한다. 최대 4일 코스의 각 일차에 적용하며 실제 여행일이 아니어도 사용자가 선택한 일차를 열 수 있다. 실제 날짜와 다른 일차는 표시로 구분한다.

각 방문 항목의 상태는 예정·완료·건너뜀이다. 완료 또는 건너뜀을 취소하면 예정으로 되돌린다. 선택 일차의 순서상 첫 예정 장소를 다음 장소로 표시한다. 모두 완료/건너뜀이면 ‘오늘 일정 확인 완료’와 완료·건너뜀 수를 따로 표시한다. 체크는 위치 인증이 아니며 보상 지급 근거가 아니다.

계정에 상태를 저장하고 다시 열 때 복구한다. 저장 실패 시 미저장 표시와 재시도를 제공하며 중복 탭으로 기록을 중복 생성하지 않는다. 같은 장소를 다른 일차에 방문하면 별개 방문 항목으로 관리한다. 순서/일차 변경은 해당 방문 항목 상태를 유지하고, 장소 교체는 예정으로 초기화한다. 삭제·재추가는 새 방문 항목이다.

진행 기록은 작성자 개인 데이터로 유지하고 읽기 전용 공유본·친구 참여 화면에 기본 공개하지 않는다. 코스를 복사할 때 진행 기록은 복사하지 않는다. 체크만으로 원래 계획 시각을 실제 도착시각으로 덮어쓰거나 남은 일정을 자동 재배치하지 않는다. 지각에 따른 자동 재계획·오프라인 동기화·실시간 위치 추적은 추가 범위다.

다음 장소를 선택하면 상세와 ‘길안내’를 제공한다. 서비스 내부의 거리·이동시간 계산은 유지하고, 실제 내비게이션은 외부 지도 앱 또는 웹으로 연결한다. 지원 가능한 자동차/도보 파라미터를 확인해 전달하고, 지원하지 않는 경우 해당 지도에서 이동수단을 다시 선택하도록 안내한다. 조용히 다른 수단으로 바꾸지 않는다. 현재 위치 권한 거절 시 외부 지도에서 출발지를 입력하거나 이전 방문지를 선택하도록 한다. 좌표 미확인 시 위치 확인을 요청한다. 앱 미설치 시 웹 대안, 연결 실패 시 주소 복사를 제공하며 구체 제공업체는 계약 전 확정한다.

## 11. 친구와 후보 함께 담기

연결: COL-01~04 · 별도 옵션

작성자는 읽기 전용 공유 링크와 별개의 참여 초대 링크를 발급한다. 초대코드는 대안 구현으로 별도 비교하며 두 방식을 동시에 요구하지 않는다. 친구는 로그인 후 유효한 초대를 수락해야 참여 권한을 얻는다. 초대 토큰의 추측 방지·만료·폐기와 참여 인원 한도를 구현 조건에 명시한다.

참여자에게는 작성자가 승인한 여행 제목·날짜·지역·장소 순서와 제안 목록만 제공한다. 참여용 미리보기에서 공개 항목을 확인한다. 개인 메모·개인 출발/종료 주소·보관함 전체·개인용 SNS 링크·당일 진행 기록은 제외한다. 참여용 열람 권한은 개인 코스 원본 데이터 전체의 조회 권한이 아니다.

친구는 등록 장소 또는 자신의 보관 장소 중 필요한 항목만 제안한다. 장소명·위치·선택적 희망 일차와 제안 코멘트를 보내며, 코멘트는 참여자에게 보임을 명시한다. 개인 메모는 자동 복사하지 않는다. 미확인 개인 장소는 위치 확인 필요로 유지한다.

제안 상태는 대기·보류·반영·거절·철회다. 친구는 자신이 작성한 대기/보류 제안만 수정·철회하며 타인의 제안이나 확정 일정은 변경하지 못한다. 작성자는 반영할 일차를 선택하고 중복·영업시간·고정 프로그램·이동 조건을 재검토한다. 시간 배치가 불가능하면 미배치 후보로 반영하거나 보류한다. 반영 후 친구의 제안 수정·철회로 확정 일정을 바꾸지 않는다.

신규 초대 닫기는 추가 참여만 차단하고 기존 참여자 권한은 유지한다. 참여자 제거는 그 사람의 참여용 열람·제안 권한을 즉시 차단하며 전체 참여 종료는 모두에게 적용한다. 이미 반영된 장소는 작성자의 일정에 남긴다. 읽기 전용 공유 해제와 참여 권한 해제는 서로 독립이며 코스 삭제 시 둘 다 차단한다. 권한·상태 전이는 서버에서 검사한다. 두 사람이 같은 장소를 제안한 경우 작성자에게 중복을 안내한다.

이번 옵션은 후보 제안과 작성자 반영이며, 실시간 공동 편집·채팅·투표·확정 일정의 동시 수정은 후속이다. 제안 목록은 재조회로 갱신할 수 있으며 실시간 연결을 필수로 하지 않는다.

## 향후 확장: 여행 코스 챌린지

사용자가 여행 코스의 장소를 방문하거나 지역별 미션을 수행하며 진행 상황을 확인하는 챌린지로 확장할 계획이다. 참여·달성 조건, 진행률 산식, 방문 인증 방식, 제휴 혜택은 미확정이며 후속 기획·별도 견적으로 결정한다. 기존 아이디어인 50%/100% 혜택은 검토 예시일 뿐 확정 정책이 아니다.

이번 개발에서는 이미 필요한 계정·코스·일차·방문 항목·장소·축제·시군의 식별과 관계를 인계 자료에 설명한다. 같은 장소를 재방문하는 일정은 방문 항목을 구분한다. 이 설명은 별도 챌린지 엔진·화면·진행률·인증·쿠폰·위치 추적 구현을 요구하지 않는다. 당일 모드를 채택하더라도 사용자의 완료 체크는 개인 기록이며 방문 인증이나 보상 지급 근거로 사용하지 않는다. 향후 코스 수정·장소 삭제 시 달성 기준을 어떻게 유지할지도 별도 설계한다.

## 정보 정확성과 운영 기준

정보 정확성은 기본 품질 요구사항이다. 자동 수집 여부와 사실 확인 여부를 구분하며, 자료 출처가 있다는 이유만으로 정확성을 보증하지 않는다.

| 정보 | 확인 기준 |
|---|---|
| 축제 기간·프로그램·변경·취소 | 주최 측·지자체 공식 안내를 우선 확인 |
| 장소 이름·지점·주소·좌표 | 동명 업체·다른 지점을 구분하고 실제 방문 위치 대조 |
| 영업시간·휴무·브레이크타임·주문/입장 마감 | 업체 공식 안내 확인, 자료가 다르거나 불명확하면 직접 문의 등으로 재확인 |
| SNS·크리에이터 장소와 순서 | 원문 또는 제작자가 제공한 정보로 확인 가능한 내용만 연결. 추정 장소·영상 순서를 실제 방문 사실로 표현하지 않음 |

운영 데이터에는 항목별 출처·확인일·확인 상태를 관리한다. 상태는 확인됨·미확인·정보 상충으로 구분하며, 확인됨은 확인 당시의 상태를 뜻한다. 마지막 확인일을 사용자에게 제공한다. 위치·영업조건이 미확인 또는 상충하면 탐색·저장은 허용하되 해당 조건이 필요한 자동 시간 배정 및 경로 판정을 확정하지 않는다. 라스트오더 등 세부 항목만 미확인이면 그 항목을 명시하고 전체 조건을 확인한 일정으로 표시하지 않는다.

발주자와 업체는 초기 수집·검증·입력 및 출시 후 갱신 담당, 초기 건수, 축제 개최 전 재확인 시점, 장소 정보 정기 점검 주기를 계약 전에 정한다. 관리자에서 출처·확인일·상태·변경 내용을 수정할 수 있어야 한다. 기존 저장 코스 재열람·재계산 시 변경된 관련 정보를 알리고 재검토하며, 사용자 일정은 확인 없이 덮어쓰지 않는다. 갑작스러운 임시 휴무나 현장 대기시간까지 실시간 보장하는 기능은 기본 과업으로 전제하지 않는다.

검수: 서로 다른 영업시간 자료, 좌표 미확인, 휴무 변경 사례를 입력하여 상태 표시·자동 배치 제한·저장 코스 재검토를 확인한다. 데이터의 실제 수집·검증 업무 비용과 관리 기능 개발 비용을 구분해 회신한다.

## 친구 공유와 향후 협업 기능의 구분

친구에게 읽기 전용 코스 링크를 보내고 받은 사람이 자신의 코스로 복사하는 기능(SHR-01~03)은 기본 견적 요청 범위로 유지한다. 친구 초대·장소 후보 제안·작성자 승인(COL-01~04)은 향후 활용을 위해 상세 기획을 보존하며 별도 옵션으로 둔다. 이번 계약에서 선택하지 않아도 기획에서 삭제하지 않는다. 실시간 공동 편집·채팅·투표는 후속 기능이다. ‘친구 기능은 나중’이라는 이유로 기본 링크 공유까지 제외하지 않는다.
