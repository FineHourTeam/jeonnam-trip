# 전남 축제 여행 플랫폼 서비스기획서

작성일: 2026-10-16 · 버전 1.4

## 1. 서비스 목적

전남의 축제와 가고 싶은 장소를 모아, 식당·카페 등 모든 장소의 영업조건과 자동차·도보 이동시간을 함께 계산·역산하여 여행 일정으로 완성한다. 이 계산은 핵심 기본 기능이다. 축제로 지역을 발견하고, SNS에서 보았던 카페·식당과 크리에이터 코스를 꺼내 자신의 여행으로 바꾸는 경험을 제공한다.

첫 개발은 모바일 중심 반응형 웹이며, 최대 3박 4일을 지원한다. 사용자는 추천 일정 또는 빈 일정에서 시작한다. 서비스명 ‘머물전남.’은 화면 검토용 가칭이다.

## 2. 주요 사용자와 문제

| 이용자 | 문제 | 제공 경험 |
|---|---|---|
| 축제 방문객 | 축제와 주변 정보가 분리됨 | 프로그램 시간에 맞춘 전후 여행 |
| SNS 장소 수집자 | 저장한 원문에서 지역·가게를 다시 찾기 어려움 | 지역·카테고리·취향으로 재검색 |
| 브이로그 참고 여행자 | 영상 순서를 직접 일정으로 옮겨야 함 | 운영팀 정리 코스 복사 후 날짜에 맞게 수정 |
| 직접 계획하는 여행자 | 지도와 시간표를 반복해 대조함 | 내부 이동정보와 편집 후 시간 검토 |

## 3. 핵심 이용 흐름

축제로 시작: 목록/달력 → 축제 상세 → 방문일/프로그램 → 주변 장소 → 코스 편집 → 저장·공유.

장소로 시작: 지역·카테고리 탐색 또는 SNS 링크 → 장소 연결 → 보관함 → 선택 장소 꺼내오기 → 날짜·이동수단 → 일정 편집.

크리에이터로 시작: 코스 상세·출처 → 내 코스로 복사 → 여행 날짜 확인 → 휴무/기간 충돌 수정 → 저장.

직접 만들기: 지역·기간 → 빈 일차 → 장소 추가 → 순서·시간 조정 → 이동 검토 → 저장.

모든 경로는 같은 일정 편집 화면에 도착한다. 탐색과 작성은 비회원도 가능하며 지속 보관할 때 로그인한다.

여행 속도는 처음 날짜·이동수단을 선택할 때 함께 고른다. ‘여유롭게/알차게’는 추천의 후보 수와 여유시간을 조정하며 별도 메뉴로 만들지 않는다. 선택은 생략할 수 있고, 직접 편집한 일정은 속도 변경만으로 자동 재배치하지 않는다.

여행 중 흐름(1차 추가 견적): 저장 코스 → 여행 시작 → 일차별 다음 장소 → 길안내 → 방문 완료 또는 건너뛰기 → 진행 상태 다시 열기. 여러 날 여행에도 적용한다. 완료 체크는 사용자 기록이며 실제 방문 인증은 아니다.

함께 준비하기(옵션): 작성자가 별도 참여 초대 → 친구 로그인·후보 제안 → 작성자가 검토·일차에 반영. 친구가 확정 일정을 직접 바꾸는 공동 편집과 구분한다. 처음에는 ‘친구와 후보 함께 담기’라는 명칭을 사용한다.

## 4. 지역과 취향 분류

| 분류 축 | 예시 | 관리 원칙 |
|---|---|---|
| 지역 | 전남 → 시군 → 동네/권역 | 행정구역과 기획 권역을 구분 |
| 기본 종류 | 카페·식당·상점·관광지·숙소 | 고정 목록으로 시작 |
| 세부 종류 | 디저트·베이커리·브런치·한식 | 상위 종류에 연결 |
| 분위기 | 오션뷰·정원·한옥·빈티지 | 주관적 태그, 개인/운영 태그 구분 |
| 목적 | 사진·데이트·혼자 쉬기·가족 식사 | 여러 개 선택 가능 |
| 이용 조건 | 주차·휴무·예약·반려동물 | 확인된 사실만 표시, 미확인 허용 |
| 발견 출처 | 인스타그램·유튜브·크리에이터 | 원문을 장소와 연결 |
| 개인 정보 | 꼭 가볼 곳·개인 메모 | 비공개 기본값 |

처음 저장할 때 상세 입력을 강제하지 않는다. 장소·지역을 모르는 SNS 링크는 미분류로 보관하고 나중에 연결하며 자동으로 위치를 알아낸다고 안내하지 않는다. 장소가 확인되면 장소 연결·지역·기본 종류를 먼저 확인하고 취향 태그는 선택적으로 추가한다. ‘감성’ 하나로 묶기보다 실제로 찾을 수 있는 구체적 태그를 사용한다.

초기에는 필터와 고정 태그를 구현한다. 깊은 중첩 폴더, 자유 태그의 자동 동의어 처리, 이미지 분위기 자동 분석은 기본 과업으로 확대하지 않는다.

## 5. 화면과 경험 원칙

탐색·보관함은 사진과 취향 중심, 일정 편집은 시간과 이동 중심으로 설계한다. 사진은 사용 가능한 이미지로 제공하며 SNS 원문 저장이 이미지 복제 권한이나 자동 수집을 뜻하지 않는다.

모바일 기본 메뉴 제안은 탐색·보관함·내 여행이며 ‘여행 만들기’를 주요 버튼으로 둔다. 모바일 일정은 목록 중심으로 지도 전환을 제공하고 PC는 일정과 지도를 함께 배치한다.

장소 저장과 일정 추가를 구분한다. 편집 중 고정 시간은 보호하고, 추천에서 누락된 후보는 이유와 함께 남긴다. 경고는 해결 동작과 연결한다. 화면 이동·로그인·조회 실패로 작성 내용이 사라지지 않게 한다.

당일 모드는 큰 체크 버튼과 다음 장소를 우선 표시한다. ‘계획 보기’로 언제든 돌아올 수 있으며 실제 길안내는 외부 지도와 연결한다. 내부 거리·시간 비교 기능은 유지한다. 친구 참여는 읽기 전용 공유와 버튼·권한을 구분하고 개인 정보 공개 범위를 보여준다.

## 6. 운영 전략

초기에는 일부 시군에서 데이터 정확성과 이용 흐름을 검증한다. 운영팀은 축제 공식 자료와 업체 정보를 확인하고 정보 항목별 출처·확인일·확인 상태를 남긴다. 자료 상충은 재확인하며 자동 수집을 검증 완료로 취급하지 않는다. 초기 입력 및 출시 후 갱신 담당과 점검 주기를 계약 전에 정한다. 홈페이지가 없는 축제도 주최·지자체 자료를 기준으로 같은 양식에 등록한다.

크리에이터 코스는 수동 검수한 코스로 시작한다. 영상 등장 순서, 확인된 여행 순서, 사용자가 수정한 코스를 구분한다. 장소 데이터가 부족하면 추천 강도를 낮추고 확인 필요 상태를 유지한다.

개발업체의 콘텐츠 입력 담당 여부와 초기 수량은 별도로 견적을 받는다. 추천 기능이 있어도 정확한 정보 수집·갱신 업무는 계속 필요하다.

## 7. 지역 연계 방향

축제와 여행으로 지역 방문을 돕고, 여행을 마친 뒤 시군별 고향사랑기부제 공식 안내 등 지역 참여로 연결하는 방향을 둔다. 축제·장소·코스의 시군 관계를 기본 데이터에 남긴다.

안내 배너와 공식 페이지 연결은 옵션 견적이다. 직접 기부 결제, 기부 인증과 자체 혜택은 관계 기관 협의 및 별도 요건 검토 후 추진한다. 기부를 여행 편집·저장의 필수 절차로 요구하지 않는다.

## 8. 출시 후 검증

축제 상세→코스 시작 비율, 저장 장소의 일정 추가, 생성→저장 완료, 충돌 수정, 재열람·재사용을 확인한다. 지표 도구 연동은 수집 범위·비용을 합의한다. 개인 메모·SNS 원문을 분석 이벤트에 그대로 전송하지 않는다.

초기 사용자 관찰에서는 장소 찾기, 프로그램 충돌 수정, 로그인 후 저장, 공유 해제까지 직접 수행하게 한다. 코스 저장을 실제 방문·숙박·소비 증가로 해석하지 않는다. 실제 효과는 별도 조사한다.

당일 모드 채택 시 완료 취소·다음 장소·재열람 복구의 편의성을 확인하고, 친구 옵션 채택 시 제안부터 작성자의 일정 반영까지 관찰한다. 체크 횟수를 실제 방문 수로 집계하지 않는다.

## 추가 기능의 도입 범위

여행 속도 통합은 기본 견적에 포함한다. 당일 모드는 1차 추가 견적으로 비용·일정을 확인한 뒤 채택한다. 친구 후보 제안은 별도 옵션이다. 전체 기존 범위와 계획 예산은 유지하고, 추가 기능 채택으로 비용이 늘어나면 항목별로 협의한다. 자동 재계획·실시간 공동 편집·직접 내비게이션 개발은 이번 추가에 포함하지 않는다.

## 향후 확장: 여행 코스 챌린지

사용자가 여행 코스의 장소를 방문하거나 지역별 미션을 수행하며 진행 상황을 확인하는 챌린지로 확장할 계획이다. 참여·달성 조건, 진행률 산식, 방문 인증 방식, 제휴 혜택은 미확정이며 후속 기획·별도 견적으로 결정한다. 기존 아이디어인 50%/100% 혜택은 검토 예시일 뿐 확정 정책이 아니다.

이번 개발에서는 이미 필요한 계정·코스·일차·방문 항목·장소·축제·시군의 식별과 관계를 인계 자료에 설명한다. 같은 장소를 재방문하는 일정은 방문 항목을 구분한다. 이 설명은 별도 챌린지 엔진·화면·진행률·인증·쿠폰·위치 추적 구현을 요구하지 않는다. 당일 모드를 채택하더라도 사용자의 완료 체크는 개인 기록이며 방문 인증이나 보상 지급 근거로 사용하지 않는다. 향후 코스 수정·장소 삭제 시 달성 기준을 어떻게 유지할지도 별도 설계한다.

## 친구 공유와 향후 협업 기능의 구분

친구에게 읽기 전용 코스 링크를 보내고 받은 사람이 자신의 코스로 복사하는 기능(SHR-01~03)은 기본 견적 요청 범위로 유지한다. 친구 초대·장소 후보 제안·작성자 승인(COL-01~04)은 향후 활용을 위해 상세 기획을 보존하며 별도 옵션으로 둔다. 이번 계약에서 선택하지 않아도 기획에서 삭제하지 않는다. 실시간 공동 편집·채팅·투표는 후속 기능이다. ‘친구 기능은 나중’이라는 이유로 기본 링크 공유까지 제외하지 않는다.
