# 전남 축제 여행 플랫폼 화면설계서

작성일: 2026-10-16 · 버전 1.4 · 텍스트 스토리보드 및 프로토타입 대응

최종 시각 디자인은 업체와 확정한다. 아래 화면 번호와 상태를 기준으로 디자인·개발 범위를 견적한다. 프로토타입은 클릭 흐름을 확인하는 독립 데모이며 실제 서비스 통합본은 아니다.

## 1. 화면 이동

탐색 홈 → 축제/장소/크리에이터 상세 → 여행 시작 설정 → 코스 편집 → 로그인 → 내 여행 → 공유 설정 → 공개 코스.

보관함 → SNS 링크 등록 → 장소 연결/직접 등록 → 보관함 → 일차 선택 → 코스 편집.

관리자 인증 → 콘텐츠 목록 → 초안 편집 → 검수·미리보기 → 공개/비공개.

| S16 | 함께 담은 후보(옵션): 여행 요약, 제안자·장소·희망 일차·상태 | 친구는 본인 미반영 제안 수정/철회, 작성자는 반영/보류/거절 | 중복·위치 미확인·권한 해제, 반영 시 시간 검토 |

S11 → S14는 저장 코스의 계획/실행 전환이다. S10 또는 S11 → S15 → 로그인·참여 수락 → S16은 옵션 흐름이며 읽기 전용 S12와 별도 권한이다.

당일 모드 예시:

```text
1일차 · 여행 중                 계획 보기
방문 완료 1 / 3곳 · 건너뜀 0곳
✓ 정원 카페                    완료 취소
→ 강변 가을축제          길안내 / 방문 완료
○ 골목 식당                    건너뛰기
```

장소 완료·건너뜀 이후 다음 예정 장소를 강조한다. 체크만으로 실제 도착 시각·방문 인증·공개 진행률을 만들지 않는다. 친구 화면은 ‘후보 제안’ 명칭을 사용하며 확정 일정의 시간·순서 편집 버튼은 작성자에게만 제공한다.

## 3. 코스 편집 화면의 배치

모바일:

```text
뒤로 / 여행 제목 / 저장
여행 날짜 · 자동차/도보
1일차  2일차  3일차  4일차
일정 보기 / 지도 보기
방문 장소 수 · 이동 합계 · 계산 상태
도착시각 / 장소 / 체류 / 출발시각
구간 이동수단·실제 경로 예상거리/시간·별도 접근 여유
영업구간·주문 마감·최종 출발 한도·충돌 이유
고정 프로그램 / 목표 도착 / 충돌 안내
미배치 장소와 이유
장소 추가·보관함에서 꺼내오기
```

PC는 왼쪽 일정과 오른쪽 실제 지도를 함께 표시한다. 장소 선택과 지도 지점 선택을 연결한다. 지도 전환 후 일차·선택·스크롤 상태를 유지한다.

장소 카드의 더보기는 시간 수정, 위/아래, 다른 일차, 교체, 삭제를 제공한다. 모바일에서 드래그만으로 편집하도록 만들지 않는다. 고정 프로그램은 시각과 잠금 문구를 표시한다.

경고는 ‘도착 시 마감’, ‘다음 프로그램 지각’, ‘영업시간 확인 필요’, ‘경로 조회 실패’를 구분한다. 사용자가 선택한 시간은 몰래 바꾸지 않고 체류 단축·방문 앞당김·다른 일차·삭제 등의 관련 동작을 제공한다.

S10 시간 검수: 식당/카페의 영업구간·브레이크타임·확인된 라스트오더와 다음 일정에서 역산한 출발 한도를 보여준다. 상세 설명은 펼쳐 볼 수 있게 한다. 장소·날짜·순서·체류·이동수단 변경 후 재계산 중/완료/실패를 구분하며 영향받는 이전·후속 장소의 충돌도 갱신한다. 사용자의 시간·순서는 확인 없이 바꾸지 않는다.

프로토타입은 각기 독립된 예시 데이터를 사용한다. 시연에서 카페 체류 30분, 프로그램 준비 10분처럼 사용한 수치는 확정 기본값이 아니다. 운영 화면의 ‘입력 충족’은 실제 사실 검증이 아니다. 코드 구문 확인은 수행했으나 실서비스 브라우저 통합 테스트·보안 검수 완료를 뜻하지 않는다.

문서에 포함된 여행 속도 통합·당일 모드·친구 후보 제안은 문서와 텍스트 스토리보드에 반영한 범위다. 기존 인터랙티브 프로토타입은 이번 개정에서 수정하지 않았으며 신규 기능이 구현된 것으로 간주하지 않는다.

### 동봉된 프로토타입 확인 방법

외주 전달 패키지의 압축을 모두 푼 뒤 `프로토타입` 폴더에서 위 대응표의 HTML 파일을 브라우저로 열어 확인한다. 별도 개발 서버나 Codex 계정 없이 화면 흐름을 살펴볼 수 있는 전달용 파일이다. 문서 5개만 있는 이전 압축본 대신 `전남여행플랫폼_외주전달_v1.4_최종정리.zip`을 사용한다.

각 파일은 독립 시연이며 서로 데이터가 연결되지 않는다. 실제 지도·경로·로그인·공유·운영 서버는 연동하지 않았다. 가상 데이터와 시연용 시간 계산을 사용하며, 저장·공개 성공 표시도 실서비스 동작을 뜻하지 않는다. 여행 속도·당일 모드·친구 후보 제안 및 v1.2의 전체 영업조건·연쇄 역산 요구사항은 시연 화면에 모두 구현된 상태가 아니다. 구현·견적·검수 기준은 최신 문서이며 차이가 있으면 업체가 확인 요청한다. 챌린지는 후속 범위다.

## 6. 디자인 검수와 인계

우선 검토할 화면은 축제 상세·보관함·코스 편집·공유 미리보기다. 색상보다 장소 저장과 일정 추가의 구분, 시간 충돌의 이해, 편집 복구가 우선이다. 글자 크기·버튼 터치 영역·키보드 조작·색 외 상태 문구를 함께 확인한다.

디자인 원본 또는 합의한 동등 자료, 화면 이동도, 공통 컴포넌트, 빈 결과·오류·처리 중 화면을 납품 범위에 명시한다. 모바일 주요 화면과 PC 일정·관리자 화면을 포함한다. 디자인 수정 횟수와 승인 후 변경 비용을 계약에 기록한다.

고향사랑기부제 안내는 축제 상세 또는 완성 코스 하단의 옵션 영역으로 둔다. 계획 중 반복 팝업이나 강제 참여는 두지 않는다.

## 향후 확장: 여행 코스 챌린지

사용자가 여행 코스의 장소를 방문하거나 지역별 미션을 수행하며 진행 상황을 확인하는 챌린지로 확장할 계획이다. 참여·달성 조건, 진행률 산식, 방문 인증 방식, 제휴 혜택은 미확정이며 후속 기획·별도 견적으로 결정한다. 기존 아이디어인 50%/100% 혜택은 검토 예시일 뿐 확정 정책이 아니다.

이번 개발에서는 이미 필요한 계정·코스·일차·방문 항목·장소·축제·시군의 식별과 관계를 인계 자료에 설명한다. 같은 장소를 재방문하는 일정은 방문 항목을 구분한다. 이 설명은 별도 챌린지 엔진·화면·진행률·인증·쿠폰·위치 추적 구현을 요구하지 않는다. 당일 모드를 채택하더라도 사용자의 완료 체크는 개인 기록이며 방문 인증이나 보상 지급 근거로 사용하지 않는다. 향후 코스 수정·장소 삭제 시 달성 기준을 어떻게 유지할지도 별도 설계한다.

## 친구 공유와 향후 협업 기능의 구분

친구에게 읽기 전용 코스 링크를 보내고 받은 사람이 자신의 코스로 복사하는 기능(SHR-01~03)은 기본 견적 요청 범위로 유지한다. 친구 초대·장소 후보 제안·작성자 승인(COL-01~04)은 향후 활용을 위해 상세 기획을 보존하며 별도 옵션으로 둔다. 이번 계약에서 선택하지 않아도 기획에서 삭제하지 않는다. 실시간 공동 편집·채팅·투표는 후속 기능이다. ‘친구 기능은 나중’이라는 이유로 기본 링크 공유까지 제외하지 않는다.
