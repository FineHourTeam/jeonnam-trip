# 전남 축제 여행 플랫폼 제안요청서

작성일: 2026-10-16 · 버전 1.4 · 업체 견적 협의용

발주 예정: 국립목포대학교 창업동아리 펠로우 쉽

## 1. 요청 목적

전남 축제와 주변 장소, SNS에서 발견한 방문지, 크리에이터 여행 코스를 연결하여 사용자가 실행 가능성을 검토한 여행 일정을 만들고 편집·저장·공유하는 반응형 웹을 개발한다. 축제는 주요 진입점이며 축제가 없는 기간에도 장소 중심으로 이용할 수 있어야 한다.

본 문서와 부속 요구사항·기능명세·서비스기획·화면설계를 기준으로 구현 가능 범위, 비용, 기간을 제안해 주십시오. 본 문서는 발주자의 제안요청서이며 계약 확정본이 아닙니다.

서비스 요약: 전남의 축제와 SNS에서 발견한 장소, 크리에이터 여행 코스를 한곳에서 탐색하고 지역·취향별로 보관한 뒤, 실제 영업조건과 자동차·도보 이동시간에 맞춰 당일부터 3박 4일까지 여행을 구성·편집·저장·공유하는 모바일 중심 웹서비스입니다.

문서 구성: 01 제안요청서(범위·견적·납품), 02 요구사항정의서(기능별 완료 조건), 03 기능명세서(처리 규칙), 04 서비스기획서(사용 경험·운영 방향), 05 화면설계서(화면·상태·동봉 시연 대응). 같은 요구사항 번호를 기준으로 회신하며 문서와 시연이 다르면 최신 문서 기준으로 질의합니다.

## 4. 별도 견적과 제외 범위

1차 추가 견적: 당일 모드(DAY-01~04). 저장 코스의 방문 완료·취소·건너뛰기, 다음 장소 강조, 자동차/도보에 맞는 외부 지도 길안내 연결과 진행 상태 저장을 묶어 금액·일정을 회신한다. 기본 견적과 합산한 총액도 제시하며, 추가 금액 확인 후 계약 포함 여부를 정한다. 서비스 내부 거리·이동시간 기능은 유지한다.

별도 옵션: 친구와 후보 함께 담기(COL-01~04), 체류 일수 자동 추천, 외부 장소 검색 연동, 구간별 자동차·도보 혼합 및 차량 회수, 고향사랑기부제 공식 안내 배너, YouTube 임베드, 이용지표 수집 도구 연동.

친구 기능은 작성자가 발급한 참여 초대 링크를 통해 로그인한 친구가 방문 후보를 제안하고 작성자가 일정에 반영하는 범위다. 읽기 전용 공유와 분리하며 친구가 확정 일정의 순서·시간을 직접 변경하는 공동 편집은 포함하지 않는다. 초대코드는 링크 방식의 별도 대안으로 견적하며 두 방식 동시 구현을 요구하지 않는다.

재확인 항목: 5일장 통합 조회, 꼭 갈 곳 보존은 이전 기획에 포함되었던 항목이다. 기본 포함 또는 추가 비용을 회신한다. 미응답을 자동 제외로 간주하지 않는다. 여행 속도 선택은 기본 견적 요청 범위다.

후속 범위: 영상 자동 분석·장소 자동 추출·SNS 자동 수집, 앱스토어 출시, 음성 내비게이션, 예약·결제, 기부 결제·기부 확인, 방문 인증·제휴 쿠폰, 실시간 공동 편집, 조석·바닷길 안전 판단.


## 정보 정확성과 운영 기준

정보 정확성은 기본 품질 요구사항이다. 자동 수집 여부와 사실 확인 여부를 구분하며, 자료 출처가 있다는 이유만으로 정확성을 보증하지 않는다.

| 정보 | 확인 기준 |
|---|---|
| 축제 기간·프로그램·변경·취소 | 주최 측·지자체 공식 안내를 우선 확인 |
| 장소 이름·지점·주소·좌표 | 동명 업체·다른 지점을 구분하고 실제 방문 위치 대조 |
| 영업시간·휴무·브레이크타임·주문/입장 마감 | 업체 공식 안내 확인, 자료가 다르거나 불명확하면 직접 문의 등으로 재확인 |
| SNS·크리에이터 장소와 순서 | 원문 또는 제작자가 제공한 정보로 확인 가능한 내용만 연결. 추정 장소·영상 순서를 실제 방문 사실로 표현하지 않음 |

운영 데이터에는 항목별 출처·확인일·확인 상태를 관리한다. 상태는 확인됨·미확인·정보 상충으로 구분하며, 확인됨은 확인 당시의 상태를 뜻한다. 마지막 확인일을 사용자에게 제공한다. 위치·영업조건이 미확인 또는 상충하면 탐색·저장은 허용하되 해당 조건이 필요한 자동 시간 배정 및 경로 판정을 확정하지 않는다. 라스트오더 등 세부 항목만 미확인이면 그 항목을 명시하고 전체 조건을 확인한 일정으로 표시하지 않는다.

발주자와 업체는 초기 수집·검증·입력 및 출시 후 갱신 담당, 초기 건수, 축제 개최 전 재확인 시점, 장소 정보 정기 점검 주기를 계약 전에 정한다. 관리자에서 출처·확인일·상태·변경 내용을 수정할 수 있어야 한다. 기존 저장 코스 재열람·재계산 시 변경된 관련 정보를 알리고 재검토하며, 사용자 일정은 확인 없이 덮어쓰지 않는다. 갑작스러운 임시 휴무나 현장 대기시간까지 실시간 보장하는 기능은 기본 과업으로 전제하지 않는다.

검수: 서로 다른 영업시간 자료, 좌표 미확인, 휴무 변경 사례를 입력하여 상태 표시·자동 배치 제한·저장 코스 재검토를 확인한다. 데이터의 실제 수집·검증 업무 비용과 관리 기능 개발 비용을 구분해 회신한다.

## 5. 발주자와 개발업체 역할

발주자는 서비스 방향·콘텐츠 정책을 정하고, 자료 제공·검수 담당자를 지정한다. 초기 자료 수집·검증·입력 담당과 수량은 계약에 명시한다. 운영자가 출처를 입력하는 것만으로 자료 정확성이 자동 검증되는 것은 아니다.

업체는 기존 코드 검토, 화면 디자인, 구현, API 통합, 배포와 요구사항 검수를 담당하는 안으로 견적을 제시한다. 제외하는 작업은 항목별로 명시한다. 기존 코드 보완과 재개발 중 권장안의 사유·비용 차이를 제시한다.

외부 계정의 소유자는 발주자로 두는 것을 원칙으로 협의한다. 업체는 발주자 명의 계정 설정과 인계 절차를 제안한다. 비밀키는 클라이언트 코드나 공개 저장소에 넣지 않는다.

## 6. 납품과 검수

납품물: 소스코드, 실행·배포 가능한 웹, 운영 화면, 데이터 구조·설정 설명, 디자인 원본 또는 합의한 동등 자료, 운영 안내서, 계정·배포·외부 서비스 인계 자료, 검수 결과와 알려진 제약.

핵심 검수 시나리오:

1. 축제 날짜·프로그램을 선택하고 주변 장소를 추가해 최대 4일 코스를 만든다.
2. SNS 원문 하나에 장소 두 곳을 연결하고 지역·태그로 찾아 일정에 넣는다.
3. 크리에이터 원본을 복사·수정해도 원본은 변하지 않는다.
4. 자동차·도보 각각 실제 조회 결과를 표시하며, 실패 시 미확정 상태를 알린다.
5. 식당·카페의 영업조건과 이동시간으로 도착·체류·최종 출발 시각을 함께 검토한다. 연속 방문 장소를 거슬러 역산하며, 브레이크타임·라스트오더·고정 공연 지각·최소 체류 부족을 안내한다. 이동수단이나 장소 순서를 바꾸면 영향 구간을 다시 계산하며 고정 프로그램을 임의 변경하지 않는다.
6. 비회원 작성 후 로그인해도 일정이 유지되고 다른 기기에서 다시 연다.
7. 별도 계정으로 비공개 접근·무단 수정을 시도해 차단을 확인한다.
8. 공개본에는 개인 메모·개인 출발/종료 주소가 없고(공개 방문 장소의 주소는 표시하며 개인 입력 장소는 공개 미리보기에서 확인), 해제한 링크는 더 이상 열리지 않는다.
9. 운영자의 축제 변경·취소가 관련 코스 열람 시 안내되며 원본 일정을 덮어쓰지 않는다.
10. 여행 속도 변경은 추천 후보 수·여유시간에 반영하되 고정 프로그램·이동시간·최소 체류를 훼손하지 않는다. 직접 작성 중인 일정은 임의 재배치하지 않는다.
11. 당일 모드 계약 시 완료 취소·건너뛰기·재열람 복구·다음 장소 갱신 및 길안내 실패 대안을 확인한다. 체크를 실제 방문 인증으로 표시하지 않는다.
12. 친구 옵션 계약 시 일반 공유 링크로 후보를 추가할 수 없는지, 친구가 확정 일정이나 타인의 제안을 변경할 수 없는지, 참여 권한 해제가 서버에서도 적용되는지 검수한다.

검수 대상 브라우저·기기, 결함 등급, 수정 기한, 하자보수 기간·대상은 계약 전 합의한다. 프로토타입의 로컬 성공 표시만으로 납품 검수를 통과할 수 없다.

| 사후 지원 | 하자보수 기간, 변경 요청의 추가 비용 기준 |

예산 내 전체 구현이 어려우면 항목별 축소 대안과 추가 비용을 제시한다. 축제·장소 보관/꺼내오기·코스 편집·자동차/도보 이동정보·계정 저장/공유를 우선 검토하되 범위를 임의 제외하지 않는다.

## 향후 확장: 여행 코스 챌린지

사용자가 여행 코스의 장소를 방문하거나 지역별 미션을 수행하며 진행 상황을 확인하는 챌린지로 확장할 계획이다. 참여·달성 조건, 진행률 산식, 방문 인증 방식, 제휴 혜택은 미확정이며 후속 기획·별도 견적으로 결정한다. 기존 아이디어인 50%/100% 혜택은 검토 예시일 뿐 확정 정책이 아니다.

이번 개발에서는 이미 필요한 계정·코스·일차·방문 항목·장소·축제·시군의 식별과 관계를 인계 자료에 설명한다. 같은 장소를 재방문하는 일정은 방문 항목을 구분한다. 이 설명은 별도 챌린지 엔진·화면·진행률·인증·쿠폰·위치 추적 구현을 요구하지 않는다. 당일 모드를 채택하더라도 사용자의 완료 체크는 개인 기록이며 방문 인증이나 보상 지급 근거로 사용하지 않는다. 향후 코스 수정·장소 삭제 시 달성 기준을 어떻게 유지할지도 별도 설계한다.

## 문서 검토 후 남은 협의 사항

아래는 미결정 항목이며 업체가 누락하거나 기본값을 임의 확정하지 않는다. 요구사항 ID는 유지한다. 문서 간 충돌은 업체가 질의해 합의 내용을 기록하며, 프로토타입이나 과거 축소안으로 최신 필수 요구사항을 대체하지 않는다.

## 친구 공유와 향후 협업 기능의 구분

친구에게 읽기 전용 코스 링크를 보내고 받은 사람이 자신의 코스로 복사하는 기능(SHR-01~03)은 기본 견적 요청 범위로 유지한다. 친구 초대·장소 후보 제안·작성자 승인(COL-01~04)은 향후 활용을 위해 상세 기획을 보존하며 별도 옵션으로 둔다. 이번 계약에서 선택하지 않아도 기획에서 삭제하지 않는다. 실시간 공동 편집·채팅·투표는 후속 기능이다. ‘친구 기능은 나중’이라는 이유로 기본 링크 공유까지 제외하지 않는다.
