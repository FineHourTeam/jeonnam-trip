# 머물전남. 운영 가이드

- 대상: 펠로우쉽 운영진(개발 지식 없이 읽을 수 있게 썼습니다)
- 근거: 과업지시서 Ⅱ-1 산출물(배포/운영 안내서), 제안요청서 「정보 정확성과 운영 기준」, 기능명세 ADM-01~03
- 기준: 2026-10-26 · 저장소 `FineHourTeam/jeonnam-trip` PR #1(`claude/full-service-redesign`) 화면

## 1. 자주 쓰는 주소

| 무엇 | 주소 |
|---|---|
| 사이트 | https://jeonnam-trip.web.app |
| 관리자 화면 | https://jeonnam-trip.web.app/admin |
| 축제 관리 | https://jeonnam-trip.web.app/admin/festivals |
| 장소 관리 | https://jeonnam-trip.web.app/admin/places |

관리자 화면은 표와 입력 칸이 넓게 보이도록 PC 크롬에서 여는 것을 권합니다.

## 2. 로그인과 관리자 추가

관리자도 사용자와 같은 로그인 화면에서 **Google 계정**으로 로그인합니다. 로그인한 계정이 관리자 명단에 있으면 `/admin`이 열리고, 없으면 "관리자 권한이 없어요"가 보입니다.

관리자를 새로 추가하는 일은 두 단계입니다. 앱 화면에서는 명단을 고칠 수 없고(보안 규칙으로 막혀 있습니다), Firebase 콘솔에서만 고칩니다.

1. 추가할 사람이 사이트에서 Google 계정으로 **한 번 로그인**합니다. 그래야 계정이 만들어집니다.
2. Firebase 콘솔 → Authentication → 사용자에서 그 사람의 이메일 줄에 보이는 **사용자 UID**를 복사합니다.
3. Firestore Database → `admins` 컬렉션 → [문서 추가]를 누르고, 문서 ID 칸에 복사한 UID를 붙여 넣습니다. 필드는 `email`(문자열) 하나면 됩니다.

관리자를 빼려면 `admins`에서 그 문서를 지웁니다. 지운 즉시 관리자 화면과 콘텐츠 수정 권한이 사라집니다.

## 3. 콘텐츠를 올리는 순서

축제·장소·크리에이터 코스 모두 같은 순서로 올립니다.

| 단계 | 화면에서 누르는 것 | 사용자에게 보이나 |
|---|---|---|
| 새로 만들기 | 목록 오른쪽 위 [새로 등록] → 이름 입력 → [임시저장하고 시작] | 보이지 않음 |
| 내용 채우기 | 칸을 채우고 [초안 저장] | 보이지 않음 |
| 공개 | [공개하기] — 아래 "공개 전 검수"에 막는 문제가 없어야 눌림 | 바로 보임 |
| 공개 중 고치기 | 고친 뒤 [초안 저장] → [공개본 갱신] | [공개본 갱신]을 눌러야 바뀜 |
| 내리기 | [비공개로] | 바로 사라짐 |

- 목록은 이름으로 찾고, 지역과 상태(임시저장 · 공개 · 비공개)로 나눠 볼 수 있습니다. 공개 중인데 고친 내용이 남아 있으면 "공개 대기 초안 있음"이 붙습니다.
- 편집 화면 오른쪽 위 [사용자 화면에서 보기]로 공개된 모습을 확인합니다.
- **공개본을 바꾸면** 그 콘텐츠를 담아 둔 사용자 코스에는 다음에 열 때 "바뀐 정보" 안내가 뜹니다. 사용자 일정은 사용자가 확인하기 전까지 자동으로 바뀌지 않습니다.

### 3-1. 공개 전 검수

[공개하기] 위의 검수 목록은 두 가지로 나뉩니다.

- **막는 문제**(고쳐야 공개됨): 이름 없음, 축제 기간이 비었거나 끝나는 날이 더 빠름, 축제 기간 밖의 프로그램, "확인됨"인데 확인일이 없음, 크리에이터 코스의 제목·크리에이터 이름·원문 링크·지역·장소 누락
- **확인할 것**(공개는 됨): 아직 확인하지 않은 정보, 좌표 없음(경로 계산에서 빠짐), 영업시간 비어 있음(자동 시간 배정에서 빠짐), 사진 출처·라이선스 없음, 검수일 없음

## 4. 칸을 채울 때 지킬 것

### 4-1. 확인 상태와 확인일

장소·축제의 위치, 영업시간(운영 일정), 기타 정보에는 각각 확인 상태를 둡니다.

| 상태 | 뜻 | 사용자 화면 |
|---|---|---|
| 확인됨 | 공식 안내나 직접 문의로 확인함. **확인일을 반드시 넣습니다** | "확인됨 · 2026. 10. 17. 기준"처럼 확인일과 함께 표시 |
| 미확인 | 아직 확인하지 않음 | "확인 필요"로 표시 |
| 정보 상충 | 자료끼리 다름 | "확인 필요"로 표시 |

위치나 영업시간이 미확인 · 정보 상충이면 사용자가 일정에 담을 수는 있지만, 그 장소의 시각은 확정하지 않고 "확인 필요"로 남깁니다. 출처(어디서 확인했는지)도 함께 적어 주세요.

### 4-2. 영업시간(장소)

- 요일마다 **영업 구간**을 넣습니다. 브레이크타임이 있으면 구간을 두 개로 나눕니다(예: 11:00~15:00, 17:00~21:00).
- 쉬는 요일은 **정기휴무**로 표시합니다. 비워 두는 것(미확인)과 정기휴무는 다르게 저장됩니다. 비워 두면 "확인 필요", 정기휴무면 그날 일정에 넣었을 때 "휴무" 충돌로 안내합니다.
- 임시 휴무·단축 영업처럼 특정 날짜만 다르면 **예외일**에 날짜를 넣습니다(예: 순천만국가정원 매월 마지막 주 월요일 휴무).
- 주문·입장 마감 시각이 따로 있으면 함께 넣습니다. 일정 계산이 마감 전에 도착하도록 맞춥니다.

### 4-3. 축제

- **개최 기간**과 별도로 **날짜별 운영시간**을 넣습니다. 운영시간이 미확인인 날은 사용자가 직접 넣는 후보로만 담깁니다.
- **프로그램**(개막식 · 공연 등)은 날짜 · 시작 · 끝 시각을 넣습니다. 사용자가 프로그램을 고르면 그 시각에 고정되고, 앞 일정은 그 시각에서 거꾸로 계산합니다.
- 축제가 취소되면 진행 상태를 **취소**로 바꾸고 변경·취소 안내를 적습니다. 상세는 보이지만 새 일정에는 담을 수 없습니다.

### 4-4. 크리에이터 코스

- 원문 링크(https://…)와 크리에이터 이름은 반드시 넣습니다. 원문과 다른 순서로 만들지 않습니다.
- **순서 기준**(영상 등장 순서 · 확인된 여행 순서 · 운영팀 제안 순서)을 골라 둡니다. 사용자 화면에 그대로 보입니다.
- 원문에서 확인할 수 없는 장소를 실제 방문지처럼 넣지 않습니다(제안요청서 「정보 정확성」).

### 4-5. 사진

- 사진마다 **출처(촬영자 · 기관)와 라이선스**를 적습니다. 사진 아래에 "사진 출처 · 라이선스"로 표시됩니다.
- 남도여행길잡이 등 공공누리 자료는 유형에 맞게 씁니다. 제4유형(출처 표시 · 상업 이용 금지 · 변경 금지)은 잘라 쓰거나 고칠 수 없습니다.

## 6. 사용자 문의에 답할 때

| 문의 | 확인할 것 |
|---|---|
| "지도가 안 떠요" | 네이버 클라우드 콘솔 → Maps → Application `jeonnam-trip` → Web 서비스 URL에 지금 주소가 등록돼 있는지 |
| "경로를 불러오지 못했어요" | 일정 화면의 [다시 시도]로 다시 조회됩니다. 계속되면 개발 담당자에게 서버 함수 상태와 네이버 Directions 사용량을 확인해 달라고 요청합니다 |
| "로그인 창이 안 열려요" | 카카오톡 · 인스타그램 안의 브라우저에서는 Google 로그인이 막힐 수 있습니다. 크롬 · 사파리로 열도록 안내합니다 |
| "공유 링크가 안 열려요" | 만든 사람이 공유를 멈췄거나 코스를 지운 경우입니다. 이미 복사한 코스는 남아 있습니다 |
| "저장한 코스가 사라졌어요" | 다른 Google 계정으로 로그인했는지 확인합니다. 로그인 전에 만든 코스는 그 기기에만 남아 있습니다 |
| "계정을 지우고 싶어요" | 내 계정 → [계정 삭제]. 저장한 코스 · 보관함 · 공유 링크가 함께 지워지고 되돌릴 수 없습니다 |

배포 · 서버 설정은 「02 빌드·배포 절차서」를 봅니다.
