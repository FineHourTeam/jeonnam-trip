# 머물전남 운영가이드

운영 담당자가 읽는 문서예요. 콘텐츠를 올리고, 관리자를 추가하고, 문제가 생겼을 때 어디부터 확인할지 적었어요.
코드를 고쳐야 하는 일은 "개발 담당자에게 요청"이라고 따로 표시했어요.

- 기준: `main` 브랜치 (2026-11-10, 라이브와 같아요)
- `main`에 머지하면 GitHub Actions가 바로 운영 주소에 배포해요.
- 빌드·배포 절차는 개발자용 문서(02)에 따로 정리해요.
- 이 문서에는 계정·비밀번호·키 값을 적지 않아요. 필요한 권한은 담당자에게 요청해 주세요.

---

## 1. 서비스 한눈에

| 항목 | 내용 |
|---|---|
| 서비스 이름 | 머물전남 |
| 한 줄 설명 | 전남 축제와 가고 싶은 장소로 만드는 여행 일정 |
| 운영 주소 | https://jeonnam-trip.web.app (커스텀 도메인 없음) |
| 관리자 화면 | https://jeonnam-trip.web.app/admin (사용자 화면 메뉴에는 링크가 없어서 주소를 직접 입력해요) |
| 화면 언어 | 한국어(기본)·영어·일본어 |
| 일정 길이 | 당일부터 최대 3박 4일 |
| 이동 경로 | 자동차 경로만 계산해요 (네이버 Directions) |
| 로그인 | 카카오, Google 두 가지 |
| Firebase 프로젝트 | `jeonnam-trip` (Blaze 요금제, 서울 리전 asia-northeast3) |

### 사용자가 하는 일

1. 축제, 장소, 크리에이터 코스 중 하나에서 시작하거나 직접 일정을 만들어요. 네 가지 모두 같은 일정 편집 화면으로 이어져요.
2. 일정 편집 화면에서 영업시간과 자동차 이동시간을 보고 순서를 정해요.
3. 보관하려면 로그인해요. 탐색과 작성은 로그인 없이도 돼요.
4. 원하면 공유 링크를 만들어요. 공유본은 공유한 시점의 사본이라, 원래 일정을 고쳐도 [공유 내용 업데이트]를 눌러야 바뀌어요. 개인 메모와 출발·종료 위치는 공유본에 들어가지 않아요.

### 운영팀이 관리하는 것

| 종류 | 관리자 화면 이름 | Firestore 컬렉션 | 주요 출처 |
|---|---|---|---|
| 축제 | 축제 | `festivals` | 남도여행길잡이(namdokorea.com) 수집 + 관리자 입력 |
| 장소 | 장소 | `places` | 남도여행길잡이 수집 + 관리자 입력 |
| 크리에이터 코스 | 크리에이터 코스 | `creatorCourses` | 남도여행길잡이 추천 코스 수집 + 관리자 입력 |
| 홈 첫 화면 사진 | (관리자 화면 없음) | 코드 안 정적 파일 | 5장 참고 |

## 2. 로그인과 관리자 추가

### 2-1. 관리자를 정하는 방법

관리자 여부는 Firestore `admins` 컬렉션에 그 사람의 UID를 이름으로 한 문서가 있는지만 봐요.

- 문서 안의 필드는 보지 않아요. 이메일 같은 개인정보를 넣을 필요가 없어요.
- 앱 화면에서는 관리자를 만들 수 없어요. 보안 규칙이 `admins` 쓰기를 모두 막고 있어서 Firebase 콘솔에서만 추가·삭제해요.
- 관리자 화면이 막히는 것은 안내용이고, 실제로 데이터를 지키는 것은 Firestore·Storage 보안 규칙이에요.

### 2-2. UID 찾는 법

UID는 로그인한 사람마다 붙는 고유 번호예요. 앱 화면에는 표시되지 않아서 Firebase 콘솔에서 찾아요.

1. 관리자로 지정할 사람에게 운영 주소에서 한 번 로그인해 달라고 요청해요. 로그인해야 계정이 만들어져요.
2. Firebase 콘솔에서 `jeonnam-trip` 프로젝트 → Authentication → 사용자 탭으로 가요.
3. 그 사람의 행에서 "사용자 UID" 값을 복사해요.

| 로그인 방법 | UID 모양 | 찾는 요령 |
|---|---|---|
| Google | 영문·숫자 조합 | 식별자 칸의 Google 계정으로 찾아요 |
| 카카오 | `kakao:<카카오 회원번호>` | 로그인 날짜가 오늘인 `kakao:` 행을 찾아요. 카카오 사용자는 닉네임만 저장해서 식별자·제공업체 칸이 비어 있고, 이메일로는 찾을 수 없어요 |

콘솔 사용자 표의 날짜 칸에는 시각이 보이지 않을 수 있어요(확인 필요). 같은 날 로그인한 카카오 사용자가 여럿이라 구분이 안 되면, 다른 사람의 로그인이 없는 시간에 한 번 더 로그인해 달라고 하거나 개발 담당자에게 확인을 요청해요.

카카오 UID는 `kakao:`까지 포함한 전체가 UID예요. 숫자만 복사하면 관리자로 인식되지 않아요.

### 2-3. 관리자 추가

1. Firebase 콘솔 → Firestore Database → 데이터 탭으로 가요.
2. `admins` 컬렉션을 열고 [문서 추가]를 눌러요.
3. 문서 ID에 2-2에서 복사한 UID를 그대로 붙여 넣어요.
4. 콘솔이 필드를 요구하면 메모용 필드를 하나 넣어요(예: 필드 `note`, 값 `운영팀`). 이메일·전화번호는 넣지 않아요.
5. 저장한 뒤 그 사람에게 https://jeonnam-trip.web.app/admin 을 새로고침해 달라고 해요.

관리자를 빼려면 `admins`에서 그 UID 문서를 삭제하면 돼요.

### 2-4. 로그인 방법별 주의

| 상황 | 동작 |
|---|---|
| 카카오톡·네이버 앱 같은 앱 안 브라우저 | Google이 로그인을 막아서 Google 버튼만 잠겨요. 카카오로 로그인하거나 외부 브라우저(크롬·사파리)로 열어요 |
| 일반 브라우저 | 카카오가 먼저, Google이 다음에 보여요. Google은 팝업 창으로 열려요 |
| 같은 사람이 카카오와 Google로 각각 로그인 | UID가 서로 달라요. 관리자 작업에 쓸 로그인 방법 하나로 정해서 그 UID를 등록해요 |

## 3. 관리자 화면으로 콘텐츠 올리기

### 3-1. 화면 구성

| 주소 | 화면 | 할 수 있는 일 |
|---|---|---|
| `/admin` | 관리자 홈 | 종류별 공개·임시저장·비공개 수를 보고 각 목록으로 가요. [새로 등록] 버튼이 있어요 |
| `/admin/festivals` 등 | 목록 | 검색, 지역·공개 상태 필터, [새로 등록] |
| `/admin/{종류}/new` | 신규 등록 | 빈 양식으로 시작해요 |
| `/admin/{종류}/{ID}` | 편집 | 내용을 고치고 아래 버튼으로 저장·공개해요 |

`{종류}`는 `festivals`(축제), `places`(장소), `creators`(크리에이터 코스) 세 가지예요.
편집 화면에는 사용자에게 보일 핵심 정보와 확인 상태를 저장 전에 훑어보는 미리보기가 있어요.

### 3-2. 공개 상태

| 상태 값 | 화면 이름 | 사용자에게 보이나요 |
|---|---|---|
| `draft` | 임시저장 | 안 보여요 |
| `published` | 공개 | 보여요 |
| `hidden` | 비공개 | 안 보여요. 이미 사용자 일정에 담긴 사본은 그대로 남아요 |

### 3-3. 편집 화면 버튼

| 버튼 | 보이는 때 | 하는 일 |
|---|---|---|
| [초안 저장] | 항상 | 아래 3-4 표처럼 상태에 따라 저장 위치가 달라요. 빈칸이 있어도 저장돼요 |
| [공개하기] | 공개 중이 아닐 때 | 이 내용으로 공개해요. 사용자 화면에 바로 반영돼요 |
| [공개본 갱신] | 공개 중일 때 | 공개본을 이 내용으로 바꾸고, 남아 있던 수정 초안을 지워요 |
| [비공개] | 공개 중일 때 | 확인 창에서 [비공개하기]를 누르면 상태만 비공개로 바뀌어요. 저장하지 않은 수정 내용은 사라지니 필요하면 먼저 [초안 저장]을 눌러요 |
| [수정 초안 버리기] | 수정 초안이 있을 때 | 공개본은 두고 저장해 둔 수정 내용만 지워요. 되돌릴 수 없어요 |

공개할 때는 검사가 더 엄격해요. 이름·지역·날짜 같은 필수 칸이 비어 있으면 "입력을 확인해 주세요. 빨간 안내가 있는 칸을 고쳐야 저장돼요."가 뜨고 저장되지 않아요. 빨간 안내가 있는 칸을 고친 뒤 다시 눌러요.

### 3-4. 상태 흐름과 초안

공개 중인 콘텐츠를 고칠 때 사용자 화면이 바로 바뀌지 않도록, 수정 내용을 별도 초안으로 보관해요.

| 지금 상태 | [초안 저장]을 누르면 | [공개하기]/[공개본 갱신]을 누르면 |
|---|---|---|
| 신규(아직 저장 안 함) | 임시저장 상태로 만들어져요 | 공개 상태로 만들어져요 |
| 임시저장 | 본문에 바로 저장돼요 (계속 임시저장) | 공개로 바뀌어요 |
| 공개 | 공개본은 그대로 두고 수정 초안(`contentDrafts`)에만 저장돼요 | 공개본이 이 내용으로 바뀌고 수정 초안은 지워져요 |
| 비공개 | 본문에 바로 저장돼요 (계속 비공개). 남아 있던 수정 초안은 지워져요 | 공개로 바뀌어요 |

```
신규 ──[초안 저장]──▶ 임시저장 ──[공개하기]──▶ 공개 ──[비공개]──▶ 비공개
                                                │  ▲
                                   [초안 저장]  │  │ [공개본 갱신]
                                                ▼  │
                                           수정 초안
                                         (공개본은 그대로)

비공개 ──[공개하기]──▶ 공개
비공개 ──[초안 저장]──▶ 비공개 (본문에 저장, 남아 있던 수정 초안은 지워져요)
```

공개 중인 콘텐츠를 열었을 때 수정 초안이 있으면 화면 위에 "공개본은 그대로 있고, 아래는 저장해 둔 수정 초안이에요."라는 안내가 보여요. 이때는 [공개본 갱신]을 눌러야 사용자에게 보여요.

### 3-5. 축제 입력 항목

| 묶음 | 항목 |
|---|---|
| 기본 정보 | 축제 이름, 지역, 진행 상태(예정대로·일정 변경·취소), 변경·취소 안내, 소개 |
| 개최 기간과 날짜별 운영 | 시작일, 종료일, 날짜별 운영 시간 |
| 프로그램 | 이름, 날짜, 시작, 종료, 장소 (날짜는 개최 기간 안이어야 해요) |
| 위치·문의 | 주소, 위도·경도, 주차 안내, 문의, 공식 안내 주소 |
| 사진 | 사진 올리기, 사진 출처 |
| 확인 상태 | 기간·프로그램 / 위치 / 기타 정보 각각의 확인 상태·출처·확인일 |

진행 상태를 "취소"로 두면 사용자는 상세를 볼 수 있지만 새 일정에 담을 수는 없어요.

### 3-6. 장소 입력 항목

| 묶음 | 항목 |
|---|---|
| 기본 정보 | 장소 이름, 지역(시군), 종류(카페·식당·상점·관광지·숙소), 세부 종류, 동네·여행 권역, 분위기 태그, 목적 태그, 소개 |
| 위치·연락 | 주소, 위도·경도, 전화 |
| 영업시간 | 요일별로 "미확인"·"휴무"·"영업" 중 고르고, "영업"이면 시간 구간을 넣어요. 특정 날짜 예외(그날 휴무, 메모)도 넣을 수 있어요 |
| 확인된 사실 | 주차, 예약, 반려동물 (미확인·가능·불가) |
| 원문 출처 | 종류(공식·인스타그램·유튜브·블로그·기타), 주소, 표시 이름 |
| 사진 | 사진 올리기 |
| 확인 상태 | 위치 / 영업시간 / 기타 정보 각각의 확인 상태·출처·확인일 |

입력값이 일정 계산에 주는 영향은 아래와 같아요.

| 입력 | 일정 계산에서 |
|---|---|
| 영업시간 "미확인" | 영업시간 제약 없이 도착 시각에 배정하고 "영업시간 확인이 필요해요"로 표시해요 |
| 영업시간 "휴무" | 그날은 쉬는 날로 계산해요 |
| 위도·경도 비움 | 경로 계산과 지도 표시에서 빠져요 |

위도·경도는 둘 다 넣거나 둘 다 비워요. 전남 범위(위도 33~36, 경도 125~128)를 벗어나면 저장되지 않아요.
시각은 `09:30`처럼 두 자리 시:분으로 넣어요.

### 3-7. 크리에이터 코스 입력 항목

| 묶음 | 항목 |
|---|---|
| 기본 | 코스 제목, 크리에이터, 채널 주소, 채널 프로필 사진 주소, 원문 주소, 태그, 소개 |
| 검수 | 순서 확인 기준, 검수일 |
| 지역 | 코스 지역 (하나 이상) |
| 일정 | 일차를 만들고 장소를 골라 넣어요. 장소마다 메모를 달고 위·아래로 순서를 바꿔요 |

순서 확인 기준은 셋 중 하나를 골라요.

| 선택지 | 뜻 |
|---|---|
| 영상 등장 순서 (실제 방문 순서 아님) | 영상에 나온 순서만 따랐어요 |
| 제작자가 확인한 실제 여행 순서 | 크리에이터가 실제로 다닌 순서예요 |
| 운영팀이 구성한 순서 | 운영팀이 짠 순서예요. 수집한 추천 코스는 모두 이 값이에요 |

코스에 넣을 장소는 "장소 이름이나 주소로 찾기"로 고르기 때문에 먼저 장소로 등록돼 있어야 해요. 사용자가 이 코스로 일정을 시작하면 최대 4일까지 복사돼요.

### 3-8. 수집 데이터를 고칠 때 주의

문서 ID가 `nd-`로 시작하는 콘텐츠는 남도여행길잡이에서 수집 스크립트로 가져온 것이에요.

- 수집한 장소의 영업시간은 출처에 없어서 비어 있고(미확인), 확인 상태도 모두 "미확인"이에요. 운영팀이 확인한 뒤 채워 주세요.
- 개발 담당자가 수집 스크립트를 다시 쓰기 모드로 돌리면 문서를 통째로 덮어써요. 관리자 화면에서 고친 내용과 번역도 함께 덮일 수 있으니, 다시 수집하기 전에 운영팀과 일정을 맞춰 달라고 요청해 주세요.

## 4. 사진·출처 표기 원칙

### 4-1. 올릴 수 있는 사진

| 조건 | 내용 |
|---|---|
| 파일 | 이미지 파일, 10MB 미만. 넘으면 "사진은 10MB보다 작은 이미지 파일만 올릴 수 있어요."가 떠요 |
| 저장 위치 | Storage `content/{종류}/{콘텐츠 ID}/` 아래에 자동으로 올라가고, 누구나 볼 수 있는 주소로 저장돼요 |
| 권한 | 관리자만 올리고 지울 수 있어요 |
| 저작권 | 직접 찍었거나, 이용 허락을 받았거나, 출처 표기 조건으로 쓸 수 있는 사진만 올려요 |

사진을 올리는 중에는 저장 버튼이 잠겨요. "사진을 올리는 중이에요. 다 올라가면 저장할 수 있어요."가 사라진 뒤 저장해요.

### 4-2. 출처 표기

| 대상 | 표기 위치 | 적는 법 |
|---|---|---|
| 축제 사진 | 편집 화면 "사진 출처" 칸 → 상세 화면 사진 아래에 그대로 보여요 | `사진: 신안군청 · 공공누리 제4유형`처럼 제공 기관과 이용 조건을 함께 적어요 |
| 장소 정보 | "원문 출처" 목록, 확인 상태의 "출처" 칸 → 상세 화면 출처 줄에 보여요 | 공식 홈페이지, 전화 확인, SNS 게시물 주소 등을 적어요 |
| 크리에이터 코스 | 크리에이터, 채널 주소, 원문 주소 | 원래 영상·글 주소를 꼭 남겨요 |

### 4-3. 남도여행길잡이 자료

남도여행길잡이 자료는 공공누리 제4유형이에요. 출처를 표시해야 하고, 상업적으로 쓸 수 없고, 바꿀 수 없어요.

- 사진은 사이트가 내려주는 그대로 쓰고 자르거나 글자를 얹지 않아요.
- 출처 문구를 지우지 않아요.
- 서비스에 유료 기능이나 광고를 붙일 계획이 생기면, 이 자료를 계속 쓸 수 있는지 먼저 확인해야 해요. (확인 필요)

## 6. 다국어 콘텐츠

### 6-1. 무엇이 번역되나요

| 대상 | 번역 위치 | 관리 방법 |
|---|---|---|
| 버튼·안내 같은 화면 문구 | `src/locales/{ko,en,ja}/*.json` | 코드 수정 → 개발 담당자에게 요청 |
| 축제·장소 이름, 소개, 주소 | 각 문서의 `i18n` 필드 | 번역 파일 + 반영 스크립트 → 개발 담당자에게 요청 |
| 크리에이터 코스 제목, 소개, 장소 메모 | 각 문서의 `i18n` 필드 | 위와 같아요 |
| 관리자 화면 | 번역하지 않아요 (한국어만) | - |

사용자는 화면 위쪽 언어 메뉴에서 언어를 바꾸고, 고른 언어는 그 브라우저에 기억돼요.

### 6-2. 번역이 보이는 조건

번역에는 번역할 때의 한국어 원문이 같이 저장돼 있어요. 화면은 지금 한국어 원문이 그때 원문과 같은 칸만 번역을 보여 줘요.
그래서 관리자가 한국어 소개를 고치면, 다시 번역하기 전까지 영어·일본어 화면에서도 그 칸은 한국어로 보여요. 고치지 않은 칸은 번역이 그대로 나와요.

### 6-3. 관리자 화면 저장과 번역 (주의)

관리자 화면에서 [공개하기]·[공개본 갱신]을 누르거나 공개 중이 아닌 콘텐츠를 [초안 저장]하면 그 문서의 `i18n` 필드가 함께 빠져요. 그 뒤로는 그 콘텐츠 전체가 영어·일본어 화면에서 한국어로 보여요.

- 저장한 뒤 영어·일본어 화면을 확인해 주세요.
- 번역이 빠졌으면 개발 담당자에게 번역 반영 스크립트(`scripts/apply-translations.mjs`)를 다시 돌려 달라고 요청해요. 고친 칸은 새 번역이 필요해요.
- 관리자 저장 때 번역을 지키도록 코드를 고칠지 개발 담당자와 정해 주세요.

### 6-4. 번역을 다시 넣는 순서 (개발 담당자 작업)

1. `scripts/data/place-i18n.json`, `festival-i18n.json`, `course-i18n.json`에 콘텐츠 ID별로 `ko`(지금 원문), `en`, `ja`를 적어요.
2. 먼저 건수만 확인해요.

   ```bash
   GCP_TOKEN=$(gcloud auth print-access-token) node scripts/apply-translations.mjs
   ```

3. 숫자가 맞으면 반영해요.

   ```bash
   GCP_TOKEN=$(gcloud auth print-access-token) node scripts/apply-translations.mjs --write
   ```

이 스크립트는 운영 데이터에 바로 써요. 보안 규칙을 거치지 않으니 프로젝트 권한이 있는 사람만 실행해요.

## 7. 자주 생기는 문제와 확인 순서

### 7-1. 한눈에 보기

| 증상 | 먼저 볼 곳 | 누가 |
|---|---|---|
| 지도 자리에 "지도 인증에 실패했어요." | 네이버 클라우드 콘솔 Web 서비스 URL | 콘솔 권한자 |
| "지도를 불러오지 못했어요." | 사용자 네트워크 | 운영 |
| "경로를 불러오지 못했어요." | 장소 좌표 → 경로 함수 로그 | 운영 → 개발 |
| 카카오 로그인 실패 | 카카오 콘솔 등록값 → 함수 로그 → 시크릿 | 개발 |
| Google 버튼이 잠겨 있어요 | 앱 안 브라우저인지 | 운영 |
| "관리자만 볼 수 있어요" | `admins` 문서 ID와 UID | 운영 |
| "권한을 확인하지 못했어요" | 네트워크 | 운영 |
| "저장하지 못했어요. 권한과 네트워크를 확인하고…" | 관리자 등록, 네트워크 | 운영 |
| 공개했는데 사용자 화면에 안 보여요 | 상태가 공개인지, 수정 초안만 저장했는지 | 운영 |
| 영어·일본어 화면에 한국어가 보여요 | 6-2, 6-3 | 운영 → 개발 |
| 화면이 흰색으로만 보여요 (브라우저 개발자 도구 콘솔에 "환경변수 누락/오류: …") | 배포 빌드의 `VITE_*` 값 | 개발 |

### 7-2. 지도가 안 떠요

네이버 지도는 네이버 클라우드 콘솔에 등록한 주소에서만 떠요.

1. 화면에 "지도 인증에 실패했어요. 등록된 서비스 주소에서만 지도를 볼 수 있어요."가 보이는지 확인해요.
2. 지금 연 주소를 확인해요.

   | 주소 | 지도 |
   |---|---|
   | https://jeonnam-trip.web.app | 등록돼 있어요. 여기서 안 뜨면 3번으로 가요 |
   | PR 미리보기 주소 (`jeonnam-trip--pr…web.app`) | 등록 여부를 확인하지 못했어요 (확인 필요) |
   | 개발자 PC (`http://localhost:5173`) | 기록이 엇갈려요 (확인 필요). 지도 확인은 운영 주소에서 해요 |

3. 네이버 클라우드 콘솔 → Maps → Application `jeonnam-trip` → Web 서비스 URL에 그 주소가 있는지 봐요. 없으면 추가해요.
4. 운영 주소에서도 안 뜨면 개발 담당자에게 Maps 사용 설정과 이용 한도를 확인해 달라고 요청해요.

### 7-3. 경로(이동시간)가 안 나와요

1. 그 장소에 위도·경도가 있는지 관리자 화면에서 봐요. 좌표가 없으면 원래 경로 계산에서 빠져요.
2. 좌표가 있는데도 여러 구간이 실패하면 개발 담당자에게 요청해요. 확인할 곳은 아래와 같아요.
   - Firebase 콘솔 → Functions → `api` 함수 로그의 `directions failed` 줄
   - 시크릿 `NAVER_MAP_CLIENT_SECRET`이 설정돼 있는지
   - `functions/.env`의 `NAVER_MAP_CLIENT_ID`가 시크릿과 같은 네이버 Application의 값인지 (짝이 맞지 않으면 경로가 실패해요)
   - 네이버 클라우드 콘솔에서 Directions 사용 설정과 이용 한도

### 7-4. 카카오 로그인이 안 돼요

카카오 로그인은 카카오 화면 → `/auth/kakao/callback` → 서버 함수 `authKakao` → 로그인 완료 순서로 진행돼요.

1. 운영 주소(https://jeonnam-trip.web.app)에서 시도했는지 확인해요. 카카오 콘솔에는 운영 주소만 등록돼 있어서 개발자 PC에서는 끝까지 되지 않아요.
2. 어디서 어떤 문구가 보였는지 기록해서 개발 담당자에게 전달해요. 토큰 교환 단계의 `KOE` 코드는 서버 함수가 받기 때문에 화면에는 나오지 않아요.

   | 보이는 곳·문구 | 뜻 | 대응 |
   |---|---|---|
   | 카카오 화면 자체에 KOE006 | 등록되지 않은 리다이렉트 주소 | 카카오 콘솔 Redirect URI에 `https://jeonnam-trip.web.app/auth/kakao/callback`이 있는지 확인 |
   | 카카오 화면 자체에 KOE101 | 앱 키 문제 | `VITE_KAKAO_JS_KEY`가 카카오 앱의 JavaScript 키인지 확인 |
   | "로그인 정보가 만료됐어요. 다시 로그인해 주세요." | 인가 코드 만료·재사용(KOE320, invalid_grant) 또는 리다이렉트 주소 불일치(KOE303) | [다시 로그인하기]로 다시 시도. 계속 되풀이되면 Redirect URI 불일치를 의심해요. 이 경우는 함수 로그에 남지 않아요 |
   | "카카오 로그인을 지금은 쓸 수 없어요. 잠시 후 다시 시도해 주세요." | 서버 쪽 설정·호출 오류 | `authKakao` 함수 로그를 확인해요 (아래 3번) |
   | "카카오 로그인 화면을 열지 못했어요." | 카카오 스크립트를 못 불러옴 | 네트워크, 광고 차단 확장 프로그램 확인 |

3. 개발 담당자가 확인할 순서예요.

   ```bash
   gcloud secrets versions list KAKAO_CLIENT_SECRET --project=jeonnam-trip
   firebase functions:list --project jeonnam-trip
   firebase functions:log --only authKakao --project jeonnam-trip
   ```

   로그에서 찾을 줄은 아래와 같아요.

   | 로그 줄 | 뜻 | 확인할 것 |
   |---|---|---|
   | `kakao token failed` + KOE010 | 클라이언트 시크릿 문제 | 시크릿 `KAKAO_CLIENT_SECRET` |
   | `kakao token failed` + KOE101 | REST API 키 문제 | `functions/.env`의 `KAKAO_REST_API_KEY` |
   | `kakao user failed` | 카카오 사용자 정보 조회 실패 | 카카오 콘솔 동의 항목, 카카오 쪽 장애 |
   | `kakao sign-in failed` | 그 밖의 서버 오류(계정 생성·토큰 발급 등) | 함수 실행 서비스 계정 권한 |

   `authKakao`는 Firebase Admin SDK 서비스 계정으로 실행되도록 코드(`functions/src/index.ts`의 `KAKAO_RUNTIME_SA`)에 정해져 있어요. 이 계정 권한을 바꾸면 로그인이 깨질 수 있어요.

### 7-5. 관리자 화면 오류

| 화면 문구 | 원인 | 확인 순서 |
|---|---|---|
| (문구 없이 로그인 화면으로 바뀌어요) | 로그인하지 않음 | 로그인하면 `/admin`으로 자동으로 돌아와요 |
| 관리자만 볼 수 있어요 | `admins`에 이 UID 문서가 없음 | 1) 지금 로그인한 방법(카카오/Google)이 등록한 UID와 같은지 2) 카카오 UID에 `kakao:`가 붙어 있는지 3) 문서 ID에 앞뒤 공백이 없는지 |
| 권한을 확인하지 못했어요 | 네트워크 문제 | 새로고침, 다른 네트워크로 다시 시도 |
| 입력을 확인해 주세요. 빨간 안내가 있는 칸을… | 필수 칸 누락이나 형식 오류 | 빨간 안내가 있는 칸을 고쳐요 (3-3 참고) |
| 저장하지 못했어요. 권한과 네트워크를… | 관리자 권한이 빠졌거나 네트워크 문제 | `admins` 문서가 남아 있는지 확인하고 다시 시도 |
| 사진을 올리지 못했어요. 다시 시도해주세요. | 업로드 실패 | 이미지·10MB 미만인지, 관리자 권한이 있는지 확인 |

### 7-6. 공개했는데 사용자 화면에 안 보여요

1. 목록에서 상태가 "공개"인지 봐요.
2. 공개 중인 콘텐츠를 고친 뒤 [초안 저장]만 눌렀다면 수정 초안에만 저장된 거예요. [공개본 갱신]을 눌러요.
3. 그래도 같으면 사용자 화면을 새로고침해요. 다른 기기에서도 같으면 개발 담당자에게 알려요.
