# 머물전남. 빌드·배포 절차서

- 대상: 저장소를 이어받아 실행·배포할 개발자
- 근거: 과업지시서 Ⅱ-1 산출물(소스코드 및 배포/운영 안내서), Ⅱ-6 검수 및 배포
- 기준: 2026-10-26 · 저장소 `FineHourTeam/jeonnam-trip`, PR #1(`claude/full-service-redesign`)
- 비밀값은 이름과 넣는 곳만 적고 값은 적지 않습니다.

## 1. 무엇이 어디에 배포되나

| 구성 | 위치 | 배포 방법 |
|---|---|---|
| 웹 화면(정적 파일 `dist/`) | Firebase Hosting 사이트 `jeonnam-trip` → https://jeonnam-trip.web.app | `main`에 푸시하면 GitHub Actions가 자동 배포. PR은 미리보기 채널(7일) |
| 서버 함수 `api` | Cloud Functions(2세대), 리전 `asia-northeast3`(서울) | 수동: `firebase deploy --only functions --project jeonnam-trip` |
| Firestore 보안 규칙·색인 | `firestore.rules`, `firestore.indexes.json` | 수동: `firebase deploy --only firestore --project jeonnam-trip` |
| Storage 보안 규칙 | `storage.rules` | 수동: `firebase deploy --only storage --project jeonnam-trip` |
| Storage 버킷 CORS | `cors.json` → 버킷 `jeonnam-trip.firebasestorage.app` | 수동: `gcloud storage buckets update gs://jeonnam-trip.firebasestorage.app --cors-file=cors.json` (docs/CORS.md) |

서버 함수는 하나입니다(`functions/src/index.ts`).

| 함수 | 하는 일 | 호출 경로 |
|---|---|---|
| `api` | 코스 편집의 자동차 경로를 네이버 Directions 5(driving)로 대신 조회합니다. 비밀키를 브라우저에 두지 않기 위해서이며, 한 번에 30구간 · 국내 좌표만 받습니다 | Hosting rewrite `/api/**` → `POST /api/directions` |

**함수를 배포하기 전에는 라이브에서 경로 시간이 나오지 않습니다**("경로를 불러오지 못했어요"). 지도 표시는 함수 없이도 됩니다.

## 2. 준비물

- Node.js 22, npm 10 이상
- Java 21: Firestore 에뮬레이터용
- Firebase CLI: `npm i -g firebase-tools` 후 `firebase login`(프로젝트 `jeonnam-trip` 권한이 있는 계정)
- Google Cloud CLI(`gcloud`): IAM · CORS · 시크릿 작업용. Firebase CLI와 같은 계정으로 로그인하고, 명령마다 `--project=jeonnam-trip`을 붙입니다
- Playwright 브라우저: `npx playwright install chromium`

## 3. 로컬에서 실행하기

```bash
npm ci
npm ci --prefix functions
npm run emulators
npm run seed:test
npm run seed:sample
npm run dev
```

- `npm run dev`는 `.env`의 `VITE_USE_EMULATORS`가 켜져 있으면 Firebase 에뮬레이터(auth 9099 · firestore 8080 · storage 9199)에 연결합니다. 실제 프로젝트 데이터는 건드리지 않습니다.
- `seed:test`는 테스트 계정(`admin@test.local` · `user@test.local` · `user2@test.local`, docs/TEST_ACCOUNTS.md)을, `seed:sample`은 시험용 축제 · 장소 · 크리에이터 코스를 에뮬레이터에만 넣습니다. 두 스크립트는 에뮬레이터 주소가 아니면 실행을 거부합니다.
- 개발 서버는 `/api/**`를 함수 에뮬레이터(기본 5001)로 넘깁니다. 함수 에뮬레이터를 함께 띄우려면 `functions/.secret.local`(커밋하지 않음)에 `NAVER_MAP_CLIENT_SECRET=…`을 넣습니다. 없으면 경로만 "불러오지 못했어요"로 보이고 나머지는 그대로 동작합니다.
- **다른 프로젝트의 에뮬레이터가 기본 포트를 쓰고 있으면** `npm run emulators:alt`(auth 19099 · firestore 18080 · storage 19199)를 쓰고, 개발 서버를 `VITE_EMULATOR_AUTH_PORT=19099 VITE_EMULATOR_FIRESTORE_PORT=18080 VITE_EMULATOR_STORAGE_PORT=19199 npm run dev`로 띄웁니다. 함수 포트도 겹치면 `FUNCTIONS_EMULATOR_PORT`로 프록시 대상을 바꿉니다.
- 네이버 지도는 콘솔의 Web 서비스 URL에 등록된 주소(`jeonnam-trip.web.app`, `localhost`)에서만 뜹니다.

## 4. 검사하기

```bash
npm run lint
npm run typecheck
npm run test -- --run
npm run build
npm test --prefix functions
npm run smoke
npm run e2e
```

| 명령 | 내용 |
|---|---|
| `npm run test -- --run` | 단위 · 화면 단위 테스트(일정 계산 엔진 · 추천 · 편집 연산 · 공유 내용 등) |
| `npm test --prefix functions` | 경로 서버 함수 테스트 |
| `npm run smoke` | 프로덕션 빌드를 띄워 공개 화면 7개가 콘솔 오류 없이 뜨는지 확인 |
| `npm run e2e` | 에뮬레이터 + 개발 서버로 핵심 흐름(여행 만들기 · 편집 · 출발지 · 저장 · 공유 · 보관함 · 관리자) 확인. 경로는 고정 응답, 네이버 지도는 막은 상태로 돈다 |

- `npm run e2e`는 에뮬레이터(`firebase.e2e.json`, 19099 · 18080 · 19199)와 개발 서버를 스스로 띄웁니다. 첫 실행에서 인증 에뮬레이터가 늦게 떠 시작 단계가 실패하면, `npm run emulators:alt`로 에뮬레이터를 먼저 띄운 뒤 다시 실행합니다.
- 배포 전에는 `npm run check:web-assets`(파비콘 · 앱 아이콘 · OG 이미지)도 통과해야 합니다.

## 5. 환경 변수와 비밀값

| 이름 | 넣는 곳 | 공개 여부 | 메모 |
|---|---|---|---|
| `VITE_FIREBASE_*` 6개 | `.env`(커밋됨), GitHub 저장소 Variables | 공개 값 | Firebase 웹 앱 설정 |
| `VITE_NAVER_MAP_CLIENT_ID` | `.env`(커밋됨), GitHub Variables | 공개 값 | 네이버 클라우드 Maps Application `jeonnam-trip`. 등록한 Web 서비스 URL에서만 동작 |
| `VITE_USE_EMULATORS` | `.env` | 공개 값 | 개발 서버에서만 쓰입니다. 프로덕션 빌드는 무시합니다 |
| `VITE_SENTRY_DSN` | GitHub Variables | 공개 값 | 오류 모니터링(넣지 않으면 꺼짐) |
| `SITE_URL` | GitHub Variables | 공개 값 | 넣으면 main 배포 뒤 웹 에셋을 실제 주소로 다시 검사합니다 |
| `NAVER_MAP_CLIENT_ID`(함수 파라미터) | `functions/.env`(커밋됨) | 공개 값 | 경로 함수가 네이버 API를 부를 때 쓰는 ID |
| `NAVER_MAP_CLIENT_SECRET` | Cloud Secret Manager(함수 시크릿) | **비밀** | 로컬 함수 에뮬레이터는 `functions/.secret.local` |
| `FIREBASE_SERVICE_ACCOUNT` | GitHub Secrets | **비밀** | 배포용 서비스 계정 `firebase-adminsdk-fbsvc@jeonnam-trip.iam.gserviceaccount.com`의 키(JSON) |

- `VITE_`로 시작하는 값은 빌드할 때 화면 코드에 그대로 들어가 누구나 볼 수 있습니다. 비밀값을 `VITE_` 이름으로 넣으면 안 됩니다.
- 배포용 서비스 계정에는 Hosting 배포 권한(`roles/firebase.sdkAdminServiceAgent`)과 **Service Usage Consumer**(`roles/serviceusage.serviceUsageConsumer`, 2026-10-26 추가)가 필요합니다. 뒤의 것이 없으면 PR 미리보기 배포가 `serviceusage.services.get` 403으로 실패합니다.

## 6. 자동 배포(GitHub Actions)

| 워크플로 | 언제 | 하는 일 |
|---|---|---|
| `react-ci.yml` | `main` · `dev` 푸시, PR | 서식(Prettier), 린트, 타입 검사, 단위 테스트, 빌드, 의존성 점검, 스모크 테스트 |
| `firebase-hosting-deploy.yml` | PR | 미리보기 채널에 배포(7일 뒤 만료). PR에 주소가 댓글로 달립니다 |
| `firebase-hosting-deploy.yml` | `main` 푸시 | 라이브 사이트에 배포, `SITE_URL`이 있으면 배포 뒤 웹 에셋 검사 |

- 배포 작업에는 `checks: write`, `pull-requests: write` 권한을 명시해 두었습니다. 저장소 기본 토큰이 읽기 전용이라 빼면 미리보기 배포가 403으로 실패합니다.
- 미리보기 채널도 실제 Firebase 프로젝트의 데이터를 씁니다. 미리보기 주소는 네이버 지도 · Google 로그인 승인 도메인에 없어 지도와 로그인이 안 될 수 있습니다.

## 7. 수동 배포

```bash
firebase deploy --only functions --project jeonnam-trip
firebase deploy --only firestore,storage --project jeonnam-trip
firebase deploy --only hosting --project jeonnam-trip
```

- 함수는 배포 전에 `functions`를 빌드합니다(`firebase.json`의 predeploy). 첫 배포에는 Blaze 요금제, Secret Manager의 `NAVER_MAP_CLIENT_SECRET`, 함수 서비스 계정의 시크릿 접근 권한이 필요합니다. CLI가 권한 부여를 물으면 승인합니다.
- 보안 규칙은 그 규칙을 쓰는 코드와 **같은 커밋**으로 바꾸고 함께 배포합니다. 관리자 명단(`admins`)은 규칙상 앱에서 쓸 수 없고 콘솔 · CLI로만 고칩니다.
- Hosting은 보통 `main` 자동 배포를 씁니다. 수동으로 배포할 때도 `npm run build`가 웹 에셋 검사를 먼저 돌립니다.

## 8. 배포 뒤 확인

1. https://jeonnam-trip.web.app 에서 탐색 → 축제 상세 → 여행 만들기 → 코스 편집까지 열어 봅니다.
2. 코스 편집에서 구간마다 "자동차 N분 · N km"가 나오는지 봅니다(함수 동작 확인).
3. 장소 상세와 코스 지도에서 네이버 지도가 뜨는지 봅니다.
4. Google 로그인 → 저장 → 내 여행 → 공유 링크를 한 번 거칩니다.
5. 관리자 계정으로 `/admin`이 열리는지 봅니다.

## 9. 되돌리기

| 대상 | 방법 |
|---|---|
| 웹 화면 | Firebase 콘솔 → Hosting → 출시 기록에서 이전 버전 [롤백], 또는 이전 커밋을 `main`에 되돌려 푸시 |
| 서버 함수 | 이전 커밋을 체크아웃하고 `firebase deploy --only functions` |
| 보안 규칙 | 이전 커밋의 `firestore.rules` · `storage.rules`로 `firebase deploy --only firestore,storage` |

## 10. 저장소 구조(요약)

| 경로 | 내용 |
|---|---|
| `src/features/*` | 화면 기능별 폴더(탐색 · 축제 · 장소 · 보관함 · 크리에이터 · 코스 편집 · 여행 · 계정 · 관리자 · 지도) |
| `src/features/planner/lib` | 일정 계산 엔진(`schedule.ts`) · 추천 · 편집 연산 |
| `functions/` | 경로 서버 함수 |
| `scripts/` | 테스트 계정 · 시험 데이터 입력(에뮬레이터 전용), 웹 에셋 검사 |
| `e2e/` | 화면 흐름 · 스모크 테스트 |
| `docs/` | 기획 문서(`proposal/`), 디자인 기준(`DESIGN.md`), 데이터 구조(`data-model.md`), 이 안내서(`handover/`) |
